# PAT-004 — 契约优先 vs 直写

> 跨边界数据交换点的实现形态。判据沿用 `PAT-001` 的双闸形态。

## 1. 触发条件(TRIG)
- **TRIG-004**:要新增一个前后端 / 模块间的数据交换点(API、op、跨模块调用)——此卡判定走契约优先(在共享 contract 包里定 schema + 注册表),还是直写。

## 2. 推荐默认
默认:**跨边界 → 契约优先**(定 Zod op + 进注册表 + 类型/路由测试守住);**纯模块内私有 → 可直写**。

## 3. 判据
### DIRECT-GATE(全过才允许直写)
- **DG-001** 纯模块内、不跨前后端 / 不跨模块边界
- **DG-002** 无第二消费者(只此一处用)
- **DG-003** 非持久对外协议(不构成需稳定的接口面)

### CONTRACT-FORCE(任一命中即契约优先)
- **CF-001** 跨前后端 或 跨模块边界
- **CF-002** 有 ≥2 消费者 / 将来会被复用
- **CF-003** 要端到端类型安全 + 注册表一致性校验
- **CF-004** 要可测可追溯(如 registry 测试守 SPEC §13 路由面)

## 4. 可观测证据 + 保守默认
| 判据 | 查什么 | 缺证据时 |
|---|---|---|
| CF-001 | 调用是否跨包(`@org/contract`)/ 跨模块目录 | 不明 → 倾向契约优先 |
| CF-004 | 有无 contract registry 测试覆盖这条路由 | 无 → 补进注册表 |

## 5. 过往应用(链 LESSON_LEDGER)

|---|---|---|---|---|---|

## 6. 反模式速查
- ❌ 跨模块直接读对方 repo(违反 no cross-module repo read 不变量)——要走对方 service 的读方法 + facade。
- ❌ 加 op 不进注册表 → 路由面漂移、registry 测试漏守。
- ❌ 前后端各写一份类型、手动同步 → 必漂;用共享 contract 包做单一真源。
