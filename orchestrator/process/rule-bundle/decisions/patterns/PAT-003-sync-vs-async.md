# PAT-003 — 同步 vs 异步(任务化)

> 耗时/后台操作的执行形态选型。判据沿用 `PAT-001` 的双闸形态。

## 1. 触发条件(TRIG)
- **TRIG-003**:一个操作可能耗时(LLM 调用、外部 API、大计算、批处理)或需在后台进行——此卡判定走同步请求-响应,还是异步任务化(建任务 → 后台执行 → 轮询/通知 → 结果)。

## 2. 推荐默认
默认:**用户可感知 且 预期 >~2s → 异步任务化**;**<~2s 且需强一致即时返回 → 同步**。

## 3. 判据
### SYNC-GATE(全过才允许同步)
- **SG-001** 实测/预估耗时 < ~1–2s
- **SG-002** 失败要即时返回给用户、无需后台重试
- **SG-003** 无需断点续 / 审计执行过程
- **SG-004** 请求生命周期内必然完成(不怕用户导航走)

### ASYNC-FORCE(任一命中即异步)
- **AF-001** 操作秒级以上(如 LLM 实测 ~40s)
- **AF-002** 要在用户导航走之后继续跑
- **AF-003** 要重试 / 续跑 / 留执行审计
- **AF-004** 要解耦"发起"与"执行"(多消费者 / 排队 / 限流)

## 4. 可观测证据 + 保守默认
| 判据 | 跑什么 | 缺证据时 |
|---|---|---|
| AF-001 | **实测一次真实耗时**(本仓 MiniMax 论点树实测 38s) | 不明 → 按可能慢,倾向异步 |
| SG-004 | 是否 fire-and-forget / 是否要后台存活 | 不明 → 倾向异步 |

## 5. 过往应用(链 LESSON_LEDGER)
| 日期 | 对象 | 落档 | 触发判据 | 结局(T+N) | Ref |
|---|---|---|---|---|---|
| 2026-06 | AI 6 节点(论点树/脚本/复盘…) | **异步**(createTask → 后台 runner → 候选 → 采纳) | AF-001(LLM 秒级)+ AF-003(可续) | 对——但暴露下方反模式 | AI pipeline |

> 教训(LED 关联):异步了,但**进行态/候选只在前端 React 态、不落库、重挂不回拉** → 用户"切页就丢"。异步必须配:任务/结果落库 + 组件重挂时 hydrate。

## 6. 反模式速查
- ❌ 把 ~40s 的 LLM 调用塞进同步请求里转圈(违反 AF-001;本仓"卡住"体感即此)。
- ❌ 异步了但状态只在客户端、没落库、不可恢复(切页/刷新即丢)。
- ❌ 异步无超时兜底,慢供应商无限挂(配请求超时,如 anthropic 客户端 150s)。
