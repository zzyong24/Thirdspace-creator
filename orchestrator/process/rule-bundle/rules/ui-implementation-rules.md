# 界面实现规则

依据当前任务的页面规格、界面规范及实际需要的组件/数据定义实现；未启用的模板不要求补齐。现有项目优先沿用已有组件和文案体系。

- 组件说明必要状态和无障碍行为；不添加需求之外的页面、操作或装饰。
- 尚未接通的操作明确显示“规划中”，不能假装完成；读写在同一任务闭环。见 `rules/product-integrity-rules.md`。
- 跨页概念复用同一套名称、格式化和时钟；读失败显示真实错误，不能回退成伪造成功数据。
- 语言按产品实际需求决定。中文产品可只支持中文；不为脚手架预设第二语言。已有国际化框架继续沿用，新增文案同步所有已声明语言并运行现有键一致性检查。无界面的项目不建语言包。
- 完成页面前，在真实浏览器或桌面环境用非固定演示数据运行声明的旅程和视口。集合变化后，选择、详情、反馈和下一步保持一致：`selectedId == null || visibleIds.includes(selectedId)`，`detail == null || detail.id == selectedId`。
- 设计与实现冲突时更新真实定义或记录偏差，不留下两个相互矛盾的版本。
- 用户文案使用产品词汇，不暴露任务 ID、代码符号、内部项目名、提交或框架术语。错误说明发生什么、用户工作是否受影响、如何继续；安全诊断标识只作为次要“参考编号”。

`frontend-validation.mjs` 校验导出的可见文本；源代码搜索仅作提前提示。复用来源写在代码或决策元数据中，不放进产品文案。
