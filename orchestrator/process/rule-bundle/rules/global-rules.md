# 公共规则

- 当前用户目标和已确认产品说明界定范围；授权与假设按 `workflows/_COMMON.md` 处理，不在此增设确认点。
- 产品、契约、代码和验收保持一致；条件追溯仅在实际启用时维护。
- 实现前阅读受影响代码和实际调用方，按具体依赖扩展检索；使用现有项目约定。
- 坦诚说明实际问题与可行替代方案，尊重用户知情选择，重要取舍写入现有决策路径。
- 外部仓库默认只读，修改需要授权。
- 修改执行、请求、观察或进程等待限制时，读 `rules/timeout-budget-rules.md`；预算和终态以真实调用链为准。

## 最小实现阶梯

新增实现前，先理解需求与真实调用链，再依次判断：是否必要 → 当前工程已有 → 标准库 → 平台/浏览器原生能力 → 已安装依赖 → 最小增量实现。命中第一个满足当前验收和运行约束的方案即停；只跳过推测性需求，不擅自删减用户明确要求。

复用先核对接口语义、目标版本和适用边界；名称相似不等于可替换。不为单次调用默认加 wrapper、factory、配置层或未来扩展点，也不为压行数牺牲可读性、信任边界校验、防数据丢失处理、安全、无障碍及项目必需测试。新增重大依赖或非平凡自研仍需取舍时，按需读 [PAT-001](../decisions/patterns/PAT-001-borrow-vs-build.md)。普通命中不建表、不逐级汇报、不增加审批。
