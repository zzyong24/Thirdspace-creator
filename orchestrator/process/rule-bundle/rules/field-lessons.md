# Field Lessons｜跨领域实战模式

本文件只在 `context-plan.mjs` 明确选择相关 pack 时读取。它保留跨不同领域仍成立的失效形状；项目名称、
供应商、任务号、事故数字和处置日记留在项目 evidence 或 case study。

## 验证与诚实

1. **局部绿色不等于真实路径成立。** 用非 fixture witness 跑一次用户实际入口，并读回最终结果。
2. **“成功但零产出”不是成功。** 同时验证状态、物理产出数量、关键字段和消费方可见结果。
3. **先单样本探针，再扩大批量。** 高成本或慢反馈链路先用最小样本验证边界与退出条件。
4. **验证边界要明说。** 不能从当前表面观察的性质，用更合适的集成测试证明，不伪称现场证据。
5. **失败按性质分流。** 固有不支持、瞬时故障、输入问题和实现缺陷使用稳定分类码与不同恢复动作。
6. **测试污染必须清理。** 验证结束后恢复用户环境；无法恢复的副作用在执行前确认。

## 数据、契约与异步工作

7. **写入和读取共享一份字段合同。** 双轨或兼容路径必须用真实输入形状回归，不能让 fixture 掩盖键名分裂。
8. **存量变化显式迁移。** 写侧修复不会自动修复旧数据；回填须幂等，并记录前后计数与回滚方式。
9. **幂等从第一个副作用开始。** 批量写入使用事务或逐项幂等键；外部副作用与本地状态之间保留可对账意图。
10. **异步状态覆盖全部终态和恢复态。** 成功、失败、取消、超时和刷新后的继续都必须可观察、可重试。
11. **输入版本固定，重试有独立标识。** 输入变化产生新工作，显式重试产生新 attempt；旧工作不得覆盖新结果。
12. **声明的策略必须有消费点。** 权限、网络、配额、沙箱或回退字段要能追到运行时消费者，否则删除声明。

## 模型、工具与协作

13. **聚焦任务只给最小上下文和工具。** 先缩小输入面、schema 与 write set，再考虑增加提示词。
14. **未知机制先做有界研究。** 官方能力、当前代码和区分性探针形成候选；连续补丁不是研究结论。
15. **静默降级等于不可诊断。** fallback、重试和替代路径留下可查询事件与安全参考编号。
16. **并发成果以工作树和验证为准。** 子任务中断后先检查差异并复验；不要凭聊天结论重做或覆盖他人修改。

## 跨平台桌面与发布闭环

17. **主机集成有四项一致性约定.** 每个支持平台对齐 command/API、shell-free argv 与路径编码、
    completion semantics 和 user copy；未支持平台诚实禁用或报错。
18. **不可变构建清单 贯穿产物身份。** 原生壳、编译产物、安装器和更新元数据消费同一身份，
    并在最终安装物中验证，而不是只看构建参数。
19. **成功必须证明 目标文件系统或主机上的实际效果。** API 返回或配置存在不能替代目标宿主行为。
20. **发布证据可在干净环境重复。** 目标运行时、安装物、关键旅程和必要平台矩阵都绑定当前 commit。

## 执行时间与观察

21. **外层完整预算覆盖内层。** 计入所有串行尝试、退避、排队、冷启动和结算余量；共享绝对deadline向内传播不重置。长任务不被单次最低值截断。
22. **观察结束保留真实任务。** 页面停止等待不是执行失败；原ID、后台终态与恢复入口必须一致。机械预算检查与公共调用链回归见 `rules/timeout-budget-rules.md`。

## 入库规则

新教训只有在另一个领域仍能复现、能写成可执行边界，并有测试或门禁承接时才进入本文件；否则留在项目
自己的 evidence/lesson。发现相似条目时合并失效形状，不追加事故叙事。
