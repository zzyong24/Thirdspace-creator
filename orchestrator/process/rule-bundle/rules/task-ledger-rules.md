# 任务看板

`BACKLOG.md` 保存执行顺序、当前状态和任务说明入口。行内简明写出目标、已完成部分与剩余工作；诊断过程和长证据保留在关联记录，不复制进每一行。

状态通过 `taskctl.mjs` 更新，不能因行内写了“完成”就绕过验收。多步骤任务完成中间步骤时仍为 🔨，最后一步才可满足 ✅ 的条件。

📋 表示待办，🔨 表示已开始未完成；“🔨 待办”等冲突先按真实进度校正。行数不是实际并发数，领取以 `progress` 的租约为准；不为降低计数删除未完成需求或伪造完成。

SessionStart 默认只提示一个队头任务，并非全量注入看板。AI 仍需读取真实看板、依赖和当前任务说明；提示不是领取授权。

## 体积维护

`backlog-health.mjs` 检测文件和行过长。现有实现：文件超过 15KB 告警、30KB 失败、60KB 返回 2；reconcile 对一般卫生债告警，对失控线报错。它们是当前运行阈值，不是需求规模限制。

用 `backlog-compact.mjs --dry-run` 预览完成项归档，再按实际需要执行；默认保留最近 5 项，活动区完成项需明确 `--all`。保留任务 ID、说明、收据和证据指针，不整体重写正在协作的看板。

可复用教训先写项目记录，只有确有跨项目价值并经过技能维护范围判断，才提炼到共享规则。
