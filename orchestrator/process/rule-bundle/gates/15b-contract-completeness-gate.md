# 契约完整性检查

> 适用判定与证据格式见 [_GATE_EVIDENCE.md](./_GATE_EVIDENCE.md)。

CONTRACT 结束、设计或实现依赖契约前执行。先按范围门判断操作是否必要，本门核对已授权操作能否实施。

- 每个操作有输入、输出、错误、权限和具体例子；适用时有状态转换、幂等或重复行为。
- 每个需要操作的 FR/核心 FLOW 有可追溯实现路径。
- 策略字段有消费位置：已有实现给 file:line，尚未实现给所属任务/模块和验收条件；BUILD/SHIP 再核对实际消费者。不得在实现前强制要求尚不存在的代码行。
- 依赖数据的需求写清来源、证据、存储/读回、历史与冷启动限制，并判定 feasible、HARD 或 cut。
- feasible 需要能力证据；HARD 需要具体候选、所有者和有界验证；cut 回到产品范围变更。没有合法来源，或削弱新鲜度、自动化、历史范围和所有权时，不能藏进 HARD。

空白、TBD、无法复查的来源、无消费计划的策略、无候选和结束条件的研究均为缺口。将缺口落实到现有决策、研究或范围变更，不添加无关字段。
