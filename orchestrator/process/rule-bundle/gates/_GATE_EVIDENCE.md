# 门的公共约定

阶段与条件门共享本文。每个门只维护自己的适用条件、检查和证据；未激活的条件不产生缺失工件义务。

## 执行与记录

在对应流程转换时执行，将 `pass`、`fail` 或 `accepted-risk` 写入已有阶段记录。普通 buildout 不额外制造审核材料。问题应修复、保持阻塞，或按用户真实授权记录风险；失败记录保留并关联修复后的结果。

## 证据

程序可判的事实需要命令与观测结果；产品、设计等判断需要被审工件和具体发现。使用项目真实验证命令，说明局部测试、模拟与真实用户旅程的不同证明范围。

| 检查 | 主要证据 |
|---|---|
| 一致性 | reconcile 输出及已启用的追溯检查 |
| 前端实现 | 适用的类型、测试、构建结果 |
| 界面旅程 | 真实运行与 frontend-validation 收据 |
| 测试驱动 | 适用行为 RED→GREEN；文案或纯样式用聚焦检查 |
| 契约 | 操作与需求对应、接口/数据验证 |
| 集成 | 真实端到端写入和读回 |

证据绑定相关工件和代码。相同环境下未变部分可复用，组合变化要补整合验证。模型共识不能推翻确定性失败；禁止排除失败用例、放宽断言或伪造早先结果。

## 风险与范围

例外使用对应范围/状态规则要求的用户 `accepted-risk` 和保留的失败证据。未触发条件不是例外。文件数量或篇幅不单独构成失败；保护实际不变量的结构限制仍有效。事故应修复具体原因，不自动扩张为永久规则。

## 记录格式

以下为兼容字段，内容使用中文：

```text
Gate: <门标识>
Status: pass | fail | accepted-risk
Evidence: <工件路径、命令或判断观察、结果>
Findings: <具体问题或无>
Decision: <继续、修订或用户接受风险>
```
