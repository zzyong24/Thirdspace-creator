# 子任务派发

仅在用户或当前规则已授权委派，且独立任务确实有助于推进时使用。不为增加 Agent 数量拆开串行前置步骤；可用工具、模型和上下文继承由宿主决定。

告知工作者具体结果、必要事实与路径、范围、依赖、验证和回报要求。引用已有上下文，不复制整个历史或规则库。只读研究只需问题和证据要求，无需写入租约。

实现任务用已有绑定和租约运行 `context-compile.mjs`。主会话通过 `taskctl.mjs` 启动任务并负责看板与集成，每个工作者领取一个任务步骤；不能凭空编造 `write_set` 或假定隔离目录已存在。

并行写入需要真实独立工作区以及无冲突的读写和共享资源边界。用 `progress.mjs batch` 检查就绪集合，遵循 `rules/parallel-collab-rules.md`。不同仓库仍可能有业务依赖。工作者只返回候选提交，不推送、不改主控制文件。

遇到阻塞，回报具体错误、已完成内容和缺失条件；不能反复重试同一权限拒绝。主会话检查实际差异、提交与验证，再串行集成。未变化产物复用有效证据，组合产生新风险时运行联调。回报说明变更、观察与未决限制，不能仅凭工作者自报通过验收。
