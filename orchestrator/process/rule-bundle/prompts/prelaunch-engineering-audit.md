# 上线前工程审计

发布准备或用户明确要求上线审查时使用。`product-audit.md` 检查用户能否完成目标；本文件检查实际上线条件。只查与产品适用的风险，不给本地工具强加网络服务、遥测或多租户架构。

结论依据当前源码、依赖行为、迁移与实际运行证据。需要独立评审且已获委派授权时可使用独立上下文；否则当前会话完成核查并说明验证范围。审计任务默认只产出发现；若用户已授权修复，则沿现有任务执行，不另造审批环节。

## 适用检查

| 领域 | 核查重点 |
| --- | --- |
| 安全边界 | 实际暴露的本机/网络接口、鉴权、文件路径边界、出网、子进程、更新签名；不可信输入不能变成指令或获得额外权限 |
| 策略执行 | 声明的网络、权限、配额、沙箱和加载白名单都有真实消费点；验证实际生效集合而非只排除几个反例 |
| 数据完整性 | 实际需要的事务、首个副作用处的幂等、多租户作用域、删除引用、重试与恢复；不以“自愈”为由破坏原数据 |
| 构建发布 | 构建不改用户数据；运行时、安装产物、版本和更新元数据一致；验证命令可在目标环境复现 |
| 检查本身 | 声称可运行的检查能实际启动；噪声先核对扫描范围，必要检查不可运行就报告阻塞 |
| 运行支持 | 用安全参考编号定位关键完成、失败、重试和异步结果；保留期覆盖真实支持需求 |

系统命令与原生 API 使用 `platform_execution_matrix`：按支持平台核对命令/API、无 shell 的参数数组与路径编码、完成语义、用户文案及不支持行为。在目标系统运行最终安装产物，并检查真实物理效果，不能仅凭开发机或 API 返回成功推断。

模型调用记录必要的模型、耗时、用量、路径与错误分类；原始提示词、响应、密钥及个人数据不得默认全量落盘。本地存储同样有隐私与泄漏风险，具体字段遵循 `rules/observability-rules.md`。优先复用已启用且适用的日志能力，不为审计新建平台。

## 结论与处置

每个问题写明受影响用户结果、具体证据、严重度和最小修复。已证实越权、数据损失或必要检查失败可阻塞；环境缺失标记待验证，不伪装为确定缺陷。推测性加固移入建议，不能自动扩展确认范围。

将报告放入项目已有证据位置；启用知识层时使用 `docs/evidence/`。按根因合并任务，复用已有授权。实际阻塞关闭、适用验收完成、必要风险获得用户决定后才可声称发布就绪；发布执行仍遵循具体授权。
