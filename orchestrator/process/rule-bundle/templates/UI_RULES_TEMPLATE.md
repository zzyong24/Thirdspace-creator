# 界面规范

DESIGN 阶段维护当前项目的视觉与交互定义。复用现有设计系统；只有实际生成或还原界面时才填写交接部分。

## 依据

记录当前视觉来源、采用决定、适用页面及尚未确认的差异。可逆样式可在已有授权内采用合理默认，不为每个颜色重复确认。

## 视觉系统

定义颜色角色、字体层级、间距、布局、圆角、响应式与无障碍要求。选定统一图标族和组件来源；多张来源图冲突时记录取舍，避免逐屏各创一套。

## 组件与文案

说明加载、空、错误、不可用和成功状态。沿用 `PRODUCT_VOCABULARY.md` 的用户语言；错误说明发生什么、用户工作是否受影响、下一步怎么做。内部 ID、原始机器码和实现术语不作为解释，安全诊断仅显示次要“参考编号”。

## 条件项：逐页生成或还原交接

```text
页面：<用户名称；内部 IA 编号只作元数据，不渲染>
视觉来源：<项目路径或链接、决定与哈希>
工具：<当前配置且可用的工具，不预设供应商>
用户目标：<可观察结果>
布局：<区域关系与信息优先级>
组件与状态：<控件、文案、空/加载/错误/正常>
数据：<真实来源或明确标记的示例>
统一样式：<引用本文件的视觉系统>
无障碍与响应式：<键盘、标签、对比度及视口>
保持：<本次不改变的区域与含义>
修改：<明确的变化>
验收：<对照来源的区域、状态与细节>
```

生成图只是候选；不因图片出现额外模块就自动扩大需求。内容冲突回到产品/页面定义解决；已确认的视觉来源与本文件保持一致。
