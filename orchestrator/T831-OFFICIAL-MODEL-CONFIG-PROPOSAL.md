## 图生图复核结论

上游确实支持图生图，且文生图和图生图是不同模型 ID：

| 能力 | 上游模型 ID | 本轮结论 |
| --- | --- | --- |
| GPT Image 2 文生图 | `openai/gpt-image-2-text-to-image` | 真实成功 |
| GPT Image 2 图像编辑 | `openai/gpt-image-2-edit` | 目录明确；正确 ID 真实调用 3/3 返回 502 暂不可用 |
| Nano Banana 2 图像编辑 | `gemini/gemini-3.1-flash-image-edit` | 目录明确；正确 ID 真实调用 2/2 返回 503 暂不可用 |

此前 `no_available_channel` 不是“上游不支持”，而是 CreatorOS 把文生图 ID 发送到了
`/images/edits`。当前还有两层缺口：

1. Growth 官方配置只允许 `image.generate`，没有独立 `image.edit` 能力；
2. CreatorOS 收到参考图时虽然会切到 `/images/edits`，但仍复用文生图模型 ID。

因此仅在 JSON 里多塞一个编辑模型既可能被校验器拒绝，也不能保证运行时选对模型。正确做法是
为官方包新增 `image.edit` 能力，参考图请求明确路由到编辑模型；同时在上游连续复测通过前，UI
要显示“当前服务不稳定/暂不可用”，不能假装已可用。
