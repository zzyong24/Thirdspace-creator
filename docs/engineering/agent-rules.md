## 一、硬规矩全文（原 AGENTS.md「硬规矩」节）


- **工作树按需创建、结束回收（用户2026-10-21纠正）**：优先复用现有合适目录；没有并行写入隔离需求时不新建工作树，确需隔离时仍守写入边界。任务结束核对独有代码并整合到主分支，保全未提交内容与不可再生证据后移除闲置工作树，不长期堆积整树、`node_modules`、`.next` 和 Rust `target`。Git保留引用与最小差量归档用于恢复，历史证据优先留外盘；有活动进程的目录不靠强删来中断工作。

- **页面沿项目原有已稳定风格（用户2026-10-19纠正）**：用户已撤销OilUI要求。新增、调整和评审页面均参照项目已有稳定页面，复用原tokens与组件，禁止再引入第二套风格；遵循[账号组页面规范](docs/features/t1022-account-group-workspace/UI_RULES.md)中原有布局、状态与真实操作原则。保留改动前基线并核对实际视觉和操作结果；产品编排、服务契约、数据隔离和适用功能验收继续执行，不另设被撤销的技能或审美评分门。

- **界面性能防复发（LED-047）**：同页弹层的链接和程序化按钮共用本地打开路径，不等待整页加载；真实页面/筛选导航保留路由。折叠大对象按需渲染；轮询必须限制在途请求并防止过期或卸载回写。改动这些路径运行 LED-047 回归，不靠删除历史或阻断合法任务提速。
- **超时预算防复发（LED-053）**：单次正执行、请求、有限结果观察与探针最短两分钟，保留更长预算；独立外层覆盖内层完整串行/重试/排队/启动及清理余量。转录、生成、渲染继承原持久任务剩余期限，耗尽立即停止，不能续期；continuous与取消仍守原归属/心跳。等待结束保留原任务ID和真实状态，不自动重发。间隔、TTL、媒体长度不是执行上限；SDK页面默认、零值及秒/毫秒单位必须查真实消费者。改动运行 `node tools/timeout-policy/verify.mjs`，至少实际公共链路回归，不仅helper；规范见 [执行超时规范](docs/engineering/timeout-policy.md)。
- **严禁假按钮**:UI 控件要么真实有效,要么删掉。
- **关键链路禁止质量门反杀可用性**:启动、保存、生成、渲染、导出、发布等上一版可完成的合法任务，
  不得因新增审美、布局或质量规则变成整单失败。存在隐藏可选图层、切换安全布局、跳过单个问题素材、
  回退基础动效等安全输出路径时必须先确定性降级；只有输入损坏、权限/归属错误或不存在任何安全输出
  路径时才允许 hard-fail。新增 fail-closed 门上线前必须有旧版成功样例、完整公共调用链回归和其判断所
  覆盖的全部输入族；孤立 helper/几何单测不能作为发布依据。
- **前后端分离**:后端业务模块不准放 `frontend/`;AI/Agent SDK 只准在 worker/ai-runtime;worker 写库经 backend service port,不直连 PG。(门卫 LED-003 执行)
- **AI 不直接写库**:只产候选,用户采纳后由 backend service 落库。
- **语义归 AI，代码守边界**:理解意图、内容归类、素材/场景匹配、创作取舍必须由可配置的
  Skill/模型完成；代码只做权限、真实 ID、类型、范围、时间、幂等、安全和用户明确选择的落实。
  禁止用写死词表、关键词计分、字符串相似度或业务名称分支冒充“智能判断”。确需确定性算法做
  去重、协议纠错或安全校验时，必须写明 `SEMANTIC_BOUNDARY_ALLOW:`、说明其不做创作选择并有测试。
- **大白话 + 配图**:给人看的设计/解释,必须有人能懂的版本 + 一张图,不只堆术语。
- **诚实置 0**:数据缺就显示真实的 0 / 空,绝不编。
- 语言：面向用户与项目工件一律使用简体中文；代码标识符、路径、命令、ID 保留英文。

## 二、原 CLAUDE.md 仍有效的条款（执行策略、检索、调研归档）

## 执行策略(场景 → 战术;hook 会注入)

- **沿用已确认账号和授权（用户2026-10-24纠正）**：本项目当前使用“月明水清深”。通过公开 CLI 解析并核对真实账号组及平台账号 ID；多个可见账号组不撤销既有选择，不再要求用户重复选择。可恢复的测试对话归属、命名、串行顺序等非阻塞问题由 Agent 自行决定、说明并继续。只有目标无法安全核实、实际操作越出现有授权或存在会产生实质影响的必要歧义，才询问缺失的最少信息；同时继续不依赖该答案的工作。技能中的“多组时询问”仅适用于没有现有选择的情况，不能覆盖用户指令。
- **只要结论、不要文件堆 → SubAgent**(它替你扛大上下文 = 天然压缩)。宽搜/调研/多视角审都走子代理。
- **并行且会改重叠文件 → worktree 隔离**(防冲突);只读并行不用 worktree。
- **检索代码一律优先 codegraph CLI(默认手段,非可选)**:找符号定义/调用链/影响面 → `codegraph query <sym> -j` / `codegraph callers <sym>` / `codegraph impact <sym>`(本仓 `.codegraph/` 已建索引,11k+ nodes)。**grep/ripgrep 只在 codegraph 够不到时兜底**——字面量、注释、配置值、跨文件字符串;**别用 grep 找符号定义/调用关系**(那是 codegraph 的活,grep 会漏会慢)。规范:orchestrator `rules/code-retrieval-rules.md`。
- **任务边界(做完一个 BACKLOG 项)→ checkpoint 进看板/记忆 + 压缩 + `codegraph index --force` 重建索引**(禁用 `sync`:增量检测不可靠会谎报最新;重建后用本次新建符号 `query` 验证),下个任务起步干净。
- 单线程小改不开子代理/worktree(有成本)。硬门用 hook 强制,战术选择是清晰触发下的判断。

原 CLAUDE.md「任务流程铁律」全文：


**单一执行真相 = `BACKLOG.md`(repo 根)。** 它是必读的任务队列看板,优先于"用户最后一句话"。

1. **需求即任务**:用户一提新需求/想法 → **立即在 `BACKLOG.md` 新建一条任务**(状态 📋,引用对应 SPEC),不靠记忆、不靠上下文。否则需求会丢(曾因此丢掉"任务调度系统")。
2. **状态强制更新**:开工把任务改 🔨 进行中;完成改 ✅ 并提交。每次状态变更都落到 `BACKLOG.md`。
3. **开工从看板顶取**,按既定顺序,不是从对话最新一句临时起意。
4. **严禁 P0/P1 分级,严禁多阶段执行(V0.1/V0.2/"第一阶段")。** 任务一旦定义清楚,就**一次从 0 到 1 做完**;需要规模时**直接起 Workflow 或并行 subagent**,不准把范围切成阶段做减法。
5. **读取顺序**:`BACKLOG.md` → 任务引用的 SPEC(`docs/superpowers/specs/`)→ 代码。设计落 SPEC,执行总账落 BACKLOG,二者不混。
6. **不写 writing-plans 式重计划**:SPEC 已足够落地;真正缺的是任务进队列。别再产出 task 级详细计划文档。
7. **宪法**:产品定位单一真值在 [docs/产品定位.md](docs/产品定位.md)。所有 SPEC / 实现对照它判"是否合定位"。改方向/架构/数据归属的 SPEC,**过审(spec-review gate,verdict≠FAIL)才准开工**(reviewer 见 orchestrator `prompts/spec-reviewer.md`,预设 MiniMax)。
8. **SPEC → 拆 Task → 过审 → 开工(不可跳步,hook 强制)**:写完一份 SPEC,**下一步必须立即把它拆成 BACKLOG 任务**(每切片一条,状态 📋,引用该 SPEC)——这一步**不靠记忆**,由 PostToolUse hook(`.claude/hooks/spec-decompose-gate.sh`,写 SPEC 即注入提醒)兜底。**SPEC 不是执行总账**;没拆 Task 进 BACKLOG = 需求没进队列 = 会丢/会直接乱开工。顺序:写 SPEC → 拆 Task 进 BACKLOG → (改架构的)过 gate → 从看板开工。**未拆 Task / 未过审,不准写实现代码。**
