# CreatorOS 产品评审与工作流重设计

> 日期:2026-06-22 · 方法:对全部 12 个页面/22 模块做交互真相审计(5 路并行审计 + Playwright 全站巡检),对标专业自媒体编导工作流与一线 AI 创作产品。
> 结论先行:**骨架对,血肉缺。当前是一个"长得像创作工具的 CRUD 数据库",离"AI 创作产品"还差一次工作流反转。**

---

## 0. 一句话诊断

CreatorOS 把内容创作建模成了**"逐页导航 + 填表 CRUD"**。但内容创作的本质不是 CRUD,而是一个 **AI 干活、人做判断的有向飞轮**。产品已经有了正确的**骨架**(七步链路 + candidate-confirm + 定位作约束 + 变现加权 + 复盘飞轮),但**五块血肉全缺**:

1. **AI 一处都没连**——Copilot 是写死的占位回复;最核心的"AI 提议→人采纳"(candidate-confirm)后端齐了却**没有任何前端按钮**;校准(盲预测)组件写完了**没挂导航**,是孤儿。
2. **核心产物是假的**——脚本编辑器富文本是假的、`保存`不落库;制作时间线/导出是本地假状态;发布排期控件全是装饰。
3. **流水线导航坏了**——六阶段 stepper 不可点;workspace 的"进入下一步"只跳 URL 不落状态,真 transition 在另一个页面(overview),两套语义打架。
4. **模块是孤岛**——复盘→选题的飞轮不闭合;跨模块零跳转(在发布中心看到一条数据,点不进对应内容/项目)。
5. **交互泄漏数据模型**——手填原始 id、手敲 ISO 时间字符串、写死恰好 3 个关键词、几十个 `href="#"` 死按钮。

> **重设计主旨(thesis):把产品从"翻页填表"反转为"Agent 驱动、你来拍板"。** 每个阶段都应是:**AI 带着上下文与素材提议 → 你审阅/编辑/采纳 → 落成真实产物 → 自动喂给下一阶段。** 这正是架构里已经设计、却没接通的 candidate-confirm 模式——它该成为**主交互**,而不是一个没接线的后端。

## 1. 评判基准:专业编导怎么干 + AI 创作产品怎么做

### 1.1 专业自媒体编导的真实流水线(我们对标的标准)

内容生产是一个**飞轮**,不是一条直线。一个成熟创作者/MCN 的链路:

| 阶段 | 专业做法 | 关键认知 |
|---|---|---|
| **选题** | 由四个源驱动:① 数据复盘(什么爆过)② 评论区/私信**需求挖掘** ③ 对标账号**拆解** ④ 热点趋势。沉淀成**选题库**,按"爆款潜力 × 定位契合 × 变现潜力"打分排序。 | **"三秒选题定生死"——选题是杠杆率最高的一步。** 工具:飞瓜/新榜/灰豚。 |
| **脚本** | 不是写散文,是写**分镜脚本**:一张表 `[口播文案 \| 画面/B-roll \| 字幕 \| 时长 \| 运镜]`,严格卡**爆款公式**:黄金3秒钩子 → 痛点共鸣 → 价值密度 → 节奏卡点 → CTA/转化钩子。 | **脚本是第二杠杆点。结构 > 文采。** |
| **搜集素材** | 围绕选题主动找:数据/案例/对标/反面素材,判断**可信度 + 与定位的相关性**,沉淀进项目。 | 像 Perplexity/秘塔——**带出处**。 |
| **拍摄/剪辑** | 按分镜拍;粗剪→精剪→**字幕+卡点+调色+封面**。留存率在这里赢/输。 | 工具是剪映/Pr/达芬奇——**别想重造 NLE**。 |
| **发布** | **一稿多平台**:同一选题按平台改写(抖音竖屏短 vs B站横屏中视频 vs 小红书图文 vs 公众号长文),每平台独立标题/封面/标签/发布时间;**矩阵号分发**。 | 分发是规模化的现实。 |
| **复盘** | 完播率/互动率/涨粉/转化按平台归因 → 提炼成**可复用方法论(爆款要素库)** → **回喂选题**。 | **这是飞轮的闭合点,整个产品的意义所在。** |
| **变现** | 内容→信任→线索→成交。内容分角色:**引流款/信任款/转化款**,漏斗追踪归因。 | 看转化不只看播放。 |

**编导的两个核心认知,本产品只半捕捉到:** ①整条链是**飞轮**(复盘回喂选题);②杠杆集中在**选题+脚本**,而产品现在把最多精力堆在了"页面好看"上。

### 1.2 一线 AI 创作产品的可借鉴范式

| 产品 | 可偷的范式 |
|---|---|
| **Notion AI / Mem** | AI **内嵌在文档里**,在你写作的地方"问 AI 起草/改写/总结",建议**就地采纳/拒绝**。 |
| **Jasper / Copy.ai** | **爆款模板** + **品牌音色**(= 我们的定位!)+ 批量生成,再人工编辑。 |
| **Opus Clip / 剪映AI / Captions / Vizard** | 长视频→自动切片、自动字幕、自动找钩子、AI数字人口播。**"AI 干 80% 的脏活,你来导演"**。 |
| **Cursor / Claude Code(agentic)** | Agent **提议 diff,你审阅+采纳**,可迭代,Agent 带上下文。**这正是 candidate-confirm。** |
| **Perplexity / 秘塔** | 带**出处/引用**的 AI 研究(= 搜集素材该长这样)。 |
| **ChatGPT/Claude Projects** | 持久**上下文**(定位+知识)注入每一次交互。 |

> **好的 AI 创作产品的共同范式:AI 起草 → 人来导演 → AI 迭代。** AI 嵌在**干活的那个点**(不是另开一个聊天框),携带**上下文**(品牌/定位/前序步骤),产出**可编辑的产物**(不是聊天文字)。人是编导,AI 是剧组。

## 2. 逐模块评审(设计/交互是否合理 + 更优范式)

评级:🟢合理 / 🟡可用但弱 / 🔴设计错位。

### 🔴 选题候选池 `/topics` — 方向错位:该 AI-first,现在是手填
- **现状**:手填表单(source 被写死为 `idea`)+ 排序 + 晋升/丢弃。受众信号"一键转候选"**永远新建**,不能挂到已有候选 → 堆重复。
- **问题**:① 选题是最高杠杆步,却**零 AI**——而数据模型里明明有 `trend/对标/需求` 来源和"AI建议";② 丢弃无确认无撤销;③ 手填角度/产品锚 id。
- **更优范式**:**选题该是 AI 主驱动的"选题会"**。Agent 自动从【评论区需求 + 对标拆解 + 趋势 + 上轮复盘】产出**打过分(爆款潜力 × 定位契合 × 变现潜力)+ 带理由 + 带出处**的候选,你只做 **采纳/丢弃/微调**。**盲预测(校准)应内嵌在这里**——发布前预测,发布后校准。对标:飞瓜选题 + 选题会 copilot。

### 🔴 脚本 `script` 阶段 — 形态错位:该是分镜表,现在是假散文编辑器
- **现状**:假富文本(工具栏按钮 toggle 但**不生效**)、`保存`只翻本地状态**不落库**(刷新即丢);"AI 写作建议"是**写死的装饰**,徽章按列表下标循环,**没有采纳按钮**;金句不能插入脚本;版本不能恢复/对比。
- **问题**:这是第二杠杆点,却**完全不可用**——既不能真编辑也不能真存。
- **更优范式**:**分镜脚本编辑器**——结构化表 `[口播 | 画面 | 字幕 | 时长]`,而非散文。**AI 按【选题+定位+研究】起草**,卡爆款公式(钩子→痛点→价值→卡点→CTA)。AI 建议**就地可采纳**(采纳一段钩子改写直接替换)。对标:Notion AI 内联 + 剪映脚本 + Jasper 模板。

### 🔴 搜集素材 `research` 阶段 — 名不副实:叫"搜集"却不能搜集
- **现状**:纯只读看板。资料类型 tab 是**装饰不过滤**;**没有任何"加来源/上传/采集"动作**。
- **更优范式**:**AI 研究 Agent**(就是我在接的那个)——给它选题,它联网搜、按定位判相关性、**带出处**返回素材,你**采纳**进项目知识。对标:Perplexity/秘塔。**这是把产品变 agent 运行时的第一个落地点。**

### 🔴 制作 `production` 阶段 — 范围错位:不该重造 NLE
- **现状**:假时间线(标注"可拖拽"但**不能拖**,不能删/裁/排序)、导出"瞬间完成"无渲染管线、素材计数全是 `assets.length` 算术假数。
- **更优范式**:**别跟剪映拼 NLE,赢不了。** 产品该拥有的是 **AI 辅助 + 交接**:生成分镜+字幕+封面文案+AI数字人口播选项 →**导出到剪映/Pr**;或 AI 自动粗剪。对标:Opus Clip / Captions / 剪映AI。**把 NLE 让出去,占住 AI-assist 和 handoff。**

### 🟡 发布中心 / 发布阶段 `publishing` — 缺了"一稿多平台"这个灵魂
- **现状**:批量上下架是真的(已修);但 tab 四选一**渲染同一视图**;简介/封面是只读 div;排期控件全装饰(**排期不可达**);"查看"是死路(点不进内容)。
- **更优范式**:**一稿多平台改写**(AI 把一份脚本适配成抖音/B站/小红书/公众号各自格式 + 每平台标题/标签/封面)+ 真日历排期 + 矩阵号分发。对标:新榜/蝉妈妈发布 + Buffer。

### 🔴 内容日历 `/calendar` — 名不副实:不是日历,是个列表
- **现状**:竖直 `<ul>`,**没有月/周网格、不能拖拽改期**;日期要**手敲毫秒级 ISO 字符串**(`2026-07-21T09:00:00.000Z`);窗口写死;只显示第一个账号**不能切**;计划项不链接到对应内容。
- **更优范式**:真日历网格 + 拖拽排期 + 日期选择器 + 账号切换;每个排期格**链接到要发的内容**,把"计划"和"生产"接起来。

### 🔴 经验沉淀/复盘 `/experience` — 飞轮不闭合 + 采集太有损
- **现状**:大部分(摘要卡/发现/分类/价值/曲线)是 fixture **inert**;"快速记录"创建一条**空洞见**的 learning;"应用经验"**默认套到第一个项目**无选择无备注;learning **不回链**到产生它的内容。
- **更优范式**:**AI 自动复盘**(拉指标→归因→提炼爆款要素→方法论库),且**必须回喂选题**(闭合飞轮)。校准(预测 vs 实际)在这里收口。

### 🟡 变现中心 `/monetization` — 归因靠手贴 id
- **现状**:漏斗 + 诚实漏损桶(**亮点,保留**);但内容归因要**手贴原始内容 id**,无选择器、无反查("这条视频带来哪些线索")——直接违背 spec 自己的 q6。
- **更优范式**:**创建内容时即打角色标签**(引流/信任/转化),通过追踪链接/UTM 自动归因,按内容角色看漏斗。诚实漏损桶很好——但要给**降低未归因的动作**。

### 🟡 知识库 `/knowledge` / 素材中心 `/assets` — 消费链路两头断
- **现状**:`/knowledge` 的"可复用片段→插入脚本"是死的;`/assets` 整套导航脚手架(类型/收藏/排序/筛选/分页/批量,~28 个控件)**全装饰**,计数 12,846 是假的与真实 list 矛盾;上传**不能选文件**(写死桩)。唯一真消费(知识→项目证据)藏在 research 工作台里,从这两页**看不见**。
- **更优范式**:素材/知识要能**反向喂给生产**("插入脚本""附到项目"),且去掉假导航(要么接,要么删——死控件是最大的信任杀手)。

### 🟡 首页 Dashboard `/` — 该是飞轮中枢,却几乎不可点
- **现状**:问候名写死"Kevin";除"新项目/开始对话"外**所有卡片只读**——待办不链项目、建议/热门选题不能一键变项目、最近发布不链内容。
- **更优范式**:Dashboard 是飞轮的**仪表盘 + 行动入口**:每张卡都该可点进对应实体、每条建议都该"一键立即创作"。

### 🔴 AI / Copilot — 产品的核心卖点,目前完全是桩
- **现状**:Copilot 提交返回写死的 *"这是本地占位回复,尚未连接真实模型"*(D-001 故意);candidate-confirm 后端齐全但**前端零采纳按钮**;校准组件写好却**未挂路由/导航**,孤儿;没有任何 per-stage AI 能力(脚本起草/多平台改写/选题打分)。
- **更优范式**:见第 3 节——这是整个重设计的核心。

## 3. 工作流级重设计(最重要的部分:更优的工作流)

逐模块修补是治标。真正的"更优工作流"是**五个结构性反转**:

### 反转一:AI 从"另开聊天框"→"嵌在每个阶段、带上下文、产可采纳产物"
- 砍掉/降级独立 Copilot 大聊天框作为主入口。改为**每个阶段一张 AI 卡**:`研究→AI找素材`、`选题→AI出选题`、`脚本→AI起草/改写`、`发布→AI多平台改写`、`复盘→AI出复盘`。
- 每张卡共享一个**Project 上下文对象**(定位 + 选题 + 研究 + 脚本 + 上轮复盘),AI 跨阶段**记得上一步**(spec §7.4 的"AI 阶段接力"——文档自己点名这是盲区)。
- 这就是把已经建好的 ai-worker / 订阅 token / candidate-confirm 接到 app(我已验证可跑真 agent)。

### 反转二:candidate-confirm 成为主交互(把产品的"心脏"接上)
- 统一的**「AI 提议 → 审阅 diff → 采纳/拒绝/再生成」**组件,复用在所有阶段。后端 `submit_candidate`/`awaiting_confirmation`/`confirmTask` 已就绪,**只差这个 UI**。
- 对标 Cursor:AI 给草稿,你像 review PR 一样采纳。**这是把"翻页填表"变"导演审片"的关键一步。**

### 反转三:打通飞轮(复盘→选题闭环 + 全局跨链)
- **复盘产出的爆款要素 → 自动变成选题候选/脚本建议**(目前完全断)。
- 全局可点穿:发布数据→点进内容→点进项目→点进脚本;线索→点进带来它的内容;learning→点进产生它的发布。**实体已经共享,只缺导航。**

### 反转四:聚焦杠杆(选题+脚本做深),非杠杆(NLE)交接出去
- 把产品力压在**选题会 copilot** 和**分镜脚本编辑器 + AI 内联**这两个最高杠杆点。
- **制作阶段不自建 NLE**,改为 AI 分镜/字幕/封面/数字人 + 导出剪映。少做,做对。

### 反转五:交互层停止泄漏数据模型
- 原始 id → 选择器;ISO 字符串 → 日期选择器;恰好3关键词 → 可增减;**死按钮(`href="#"`/无 handler)全部要么接通要么删除**——几十个装饰控件让真实编导分不清什么能用,是当前最大的体验杀手与信任杀手。

## 4. 优先级路线图(从"设计稿"到"真 AI 创作工具")

按"杠杆 × 现状缺口"排序:

| 优先级 | 工作流闭环 | 具体动作 | 为什么先做 |
|---|---|---|---|
| **P0** | 接通 AI 主交互 | ① 搜集素材真 agent(已在做)② 通用 candidate-confirm「采纳」组件 ③ 脚本 AI 起草/改写内联采纳 | 没有这个,"AI 创作产品"这句话不成立 |
| **P0** | 修复流水线导航 | stepper 可点 + 统一一个"进入下一步"(落状态)+ 脚本真落库 | 否则连一条内容都走不完 |
| **P1** | 选题会 + 校准 | 选题 AI 出候选(打分+出处)+ 把孤儿 calibration 挂上、盲预测内嵌选题/复盘 | 最高杠杆点 + 飞轮的预测端 |
| **P1** | 闭合飞轮 | 复盘→选题回喂 + 全局跨链点穿 | 飞轮是整个产品的意义 |
| **P2** | 发布升级 | 一稿多平台改写 + 真日历(网格/拖拽/日期选择器)+ 矩阵分发 | 规模化分发 |
| **P2** | 清理信任债 | 删/接所有装饰按钮、id→选择器、ISO→日期选择器、假计数→真数据 | 体验与信任的地基 |
| **P3** | 制作交接 | AI 分镜/字幕/封面/数字人 + 导出剪映(不自建 NLE) | 聚焦,不浪费在重造轮子 |

## 5. 一段话总结给决策

CreatorOS 的**架构判断是对的**——七步链路、定位作约束、变现加权、candidate-confirm、复盘飞轮,这些是真懂内容生产的人才会设计的骨架,远超普通"AI写作工具"。但它现在停在**"把骨架画成了好看的静态稿"**:AI 没连、产物是假、飞轮没转、模块是岛、交互泄漏模型。

**最短的"变成真产品"路径不是再加模块,而是做一次工作流反转:让 Agent 驱动每个阶段、让人只做采纳判断、让复盘回喂选题。** P0 的三件事(搜集素材真 agent + candidate-confirm 采纳组件 + 脚本 AI 内联)一旦接通,产品就从"设计稿"跨进"能用的 AI 创作工具"——而这三件事的后端**已经建好了**,缺的只是把线接上。
