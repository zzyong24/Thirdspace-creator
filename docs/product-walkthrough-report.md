## 二、🔴 严重问题(影响可用性 / 误导用户)

### 1. 采集完全跑不通,且**静默失败无任何反馈**(T-144)
自动化页 3 个采集任务已配好,点「立即运行」后 `external_sources` 仍 = 0、采不到数据,**前端没有任何错误提示**。用户点了采集,既没数据也没报错,完全一脸懵。根因:扫码只建登录态、没建 external_source 采集源,采集器 fallback 到已退役的 canonical 源。**静默失败比报错更伤体验。这是飞轮数据回流的总闸。**

### 2. 账号连接状态**三处不一致 + 虚假承诺**
- 设置→账号绑定:「抖音 **已连接** · 登录态有效,**可采集**你的作品数据与评论」;
- 首页账号切换器:「当前抖音号:**未绑定账号**」;
- 实测:采集 0 条、`external_sources`=0。

三处状态互相矛盾,「可采集」是**虚假承诺**(登录态 ≠ 能采集,缺 external_source)。用户被"已连接可采集"误导去点采集,空手而归还没报错。

## 三、⚠️ 中等问题(体验瑕疵)

### 3. "七步"废弃文案**跨多页系统性残留**
- 选题页:「一键晋升为 Project(**七步③**)」;
- 内容日历页:「发布节奏…(**七步⑦ · §7.2**)」;
产品早改成**两阶段**(脚本→复盘),但"七步流水线"的编号(③/⑦)散落在多个页面副标题里没清。这是**系统性文案残留**(不止一处),建议全局搜"七步"清一遍。

### 4. AI 出的选题采纳后归类为"手动灵感"
明明是 AI 出题采纳的,选题池却把来源统计到「**手动灵感 1**」,而不是「AI 选题」来源。归类逻辑不对,"选题来源"统计会失真。

### 5. 「使用情况分析」默认开着(隐私问题)
偏好设置里 `pref-analytics` 默认 = 开(checked=true)。但产品是隐私优先的本地软件,`docs/PROTECTION.md` §4 明确「任何 telemetry 默认关 / 零收集」。**分析默认开与自己的隐私原则矛盾**,对一个主打"数据不出本机"的产品是信任伤害。应默认关。

## 四、💡 小问题 / 打磨项

6. **AI 没严格遵循数量** —— 要"3 个"选题给了 8 个(选题池"多候选"逻辑,单看合理,但没尊重用户明确数量)。
7. **保存无成功提示** —— 账户昵称点保存,名字立即变了(隐式反馈),但**无 toast「已保存」**,用户不确定成没成功。
8. **技能列表部分缺友好名** —— `chatbox.distill`、`script.review` 直接显示原始 ID(「chatbox.distill chatbox.distill」),其他技能有中文名+描述,不一致。
9. **账号切换器 cursor 是 default** —— 可点击元素习惯用手型(pointer)光标。
10. **上传 file input `accept=""`** —— 不过滤到支持类型(图/视频/音频/文档/字幕),且 `multiple=false` 不支持多选。
11. **`@ai-sdk/anthropic` 编译警告刷屏** —— dev 日志反复打(纯 ESM + serverExternalPackages),运行时无害(dispatch 全 200、AI 真能跑),但噪音大。已评估:改 next.config 有破坏打包风险,暂不动。
12. **空态用 404 表达** —— 无定位母版时 `positioning.getProfile` 返回 404(OwnershipError),正常使用也刷 404 污染网络/错误日志(前端已优雅处理成空态,功能无碍,但语义糙)。

## 七、整体评价

**成熟度(主观):创作侧 + AI ≈ 85 分,数据回流侧 ≈ 30 分(卡采集)。**

- 产品的"创作引擎"已经是**能打的成品** —— 创作侧 + AI 流畅专业,超出"半成品"预期;
- 唯一挡住"完整闭环"的是**采集**(数据进不来,护城河"越用越准"转不起来);
- 第二伤是**账号状态误导**(说可采集其实不行)。

**修复优先级建议:**
1. **P0 修采集 T-144** + 采集失败给诚实反馈;
2. **P0 修账号状态一致性**(#2:别虚假承诺"可采集");
3. **P1 隐私默认**(#5 分析默认关);
4. **P1 文案对齐**(#3 清"七步"、#4 修 AI 选题来源归类);
5. 其余打磨项(#6-#12)低优先。

**一句话:这个产品比它自己看起来完整得多——创作侧是能用的成品,就差"把真实数据这根管子接上",以及别在账号状态上误导用户。**

## 八、补充发现(继续细测·选题页深测)

### ⚠️ 新增中等:选题流转漏斗计数不准
候选「AI工具用了一堆」DB 状态 = `promoted`(已立项,且真建了 project-85),但选题页**流转漏斗显示「已立项 0 / 待补充 1」**——`promoted` 状态没被计入「已立项」计数。用户看漏斗会误以为没立项过。连库实测坐实(candidates.status=promoted,projects 表有对应项目)。

### ✅ 再次验证 AI 能用 + 出色的自我感知
点「基于定位出题」→ 调通 minimax 出 8 条,且 AI **自我感知无定位母版** → 警告「这批没定位依据、会污染候选池」→ 主动提议「先产一份定位提案」。编导 agent 行为很成熟。

### 💡 小:无定位时"基于定位出题"仍先出无依据选题
理想应先引导建定位再出题;当前是先出 8 条再由 AI 软警告要清掉(优雅兜底,但严格说交互次序可优化)。

### ✅ 建项目双路径均通(连库确认)
`projects` 表实有 2 条:立项建的 `project-85`(AI工具用了一堆) + 模态建的 `project-199`(QA测试项目),status 均 active。选题→立项→建项目、手动模态建项目,两条路径都真落库。

### 🔴 新增严重:全局搜索完全不可用(索引压根是空的)
搜「AI工具」(我刚建的项目标题)→ **项目 0 / 知识 0 / 素材 0 / 视频 0,找到 0 个结果**。连库实测:`search_documents` **总量 = 0**——建了 2 个项目后索引仍 0 条,**create 路径根本不写索引**。**修正之前(项目状态评审)"只有 video tab entityType 错配"的判断——实测整个搜索索引是空的,搜索对任何词都返 0,功能形同虚设。** 需在实体写入路径挂 `upsertDocument` + 启动全量重建。(搜索历史倒是正常记录了查询词。)
