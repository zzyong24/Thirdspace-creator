# T-721 素材包导出隔离与素材完整分页 SPEC

## 用户问题

素材包导出后被作为普通“文档素材”重新写入素材中心。下一次导出项目素材时，这个 ZIP 又会被装进新的 ZIP，形成递归嵌套，文件体积持续增长。与此同时，素材中心和项目素材读取存在固定条数上限，素材较多时旧素材可能在界面或导出链路中不可见。

## 已核实根因

- 生产导出链路通过 `createGeneratedAsset(... application/zip)` 保存导出包，因此导出产物拥有普通素材记录和项目可见性。
- 素材包组装没有排除既有归档文件，历史 ZIP 可再次进入后续素材包。
- 素材中心只读取第一页 200 条；项目素材导出只读取第一页 100 条。

## 产品规则

1. “导出素材包”是一次性下载产物，不是创作素材。它只写入对象存储并返回短时下载地址，不创建 `assets` 记录，也不自动关联项目。
2. 已经进入素材中心的历史 ZIP 不擅自删除；后续导出时统一排除归档文件，阻断递归。
3. 素材中心与项目素材查询必须完整分页加载。分页以服务端 `hasNext` / 返回数量为准，并有去重和无进展保护，不能使用固定总条数截断。
4. 图片、视频、音频、字幕和普通文档仍按既有规则导出；归档隔离只做容器安全，不参与创作语义判断。
5. 导出失败不得留下半成品素材记录；现有用户项目、素材和历史导出包均不清理。

## 验收

- 连续导出两次后，素材中心数量不因导出包增加，第二个 ZIP 内不包含第一个 ZIP。
- 历史 `application/zip` 素材仍可见、可下载，但不会进入新素材包。
- 超过 200 条的素材中心能看到旧素材；超过 100 条的项目素材均可参与导出。
- 聚焦测试覆盖：下载产物零素材落库、归档排除、素材中心完整分页、项目素材完整分页、分页无进展保护。
