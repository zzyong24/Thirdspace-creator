# SPEC:编导受控自主运行时(环境感知 + 自主任务循环交给专门引擎)

> 日期 2026-07-12 · 状态:⚠️ **CONCERNS(MiniMax gate)→ 已逐条处置 → 可开工(待用户审)**(见 .review.md) · 对照宪法 [docs/产品定位.md](../../产品定位.md)
> 单一执行总账在 [BACKLOG.md](../../../BACKLOG.md)。来源:用户表态——「想让编导像 Claude Code/Codex 一样感知电脑环境、最大限度拓展手脚」+「我们给了工具、也写了 loop,但毕竟不如别人专门的 agent 设计得好;选题调研/数据抓取/素材抓取这些不是一成不变的脚本」。**本 SPEC 吸收并升级 T-255b**(从「一个 taskType 的 executor」升级为「受控自主任务运行时」)。

## 0. 一句话

编导今天「能想不能久干」:对话循环是我们自研的通用循环,不为自主多步任务优化;而选题调研/数据抓取/素材抓取本质是**边做边决策的自主循环**,最吃 loop 质量,恰是我们最弱、专门 agent 引擎(Pi/OpenCode)最强的地方。方案:**三种循环各归各位**——对话循环留自研,确定性活留脚本,**自主任务循环交给专门引擎**,但引擎只负责「想」(编排决策),真正的副作用执行(尤其浏览器抓取)仍走我们的**确定性端口**(限流/防封/登录态烤在端口里);外加**环境感知**扩展(local.read → 目录列举+工具探测)。得到「感知环境 + 受控地能干」的编导,而不丢垂类壁垒与封号纪律。

## 1. 问题(用户表态 + 现状实锤)

- **loop 质量差距真实存在**:chat-runner 是通用对话循环(T-239 加固过重试/历史窗口/中断),但没有为「自主多步任务」优化——缺少专门引擎那种成熟的 observe→decide→act→repeat、循环内错误恢复、「何时算完成」判定、循环内上下文管理。用户原话:「我们写了 loop,毕竟没有别人专门的 agent 设计得更好」。
- **三个例子都是自主循环、非脚本**:选题调研(搜→读→判断够不够→再搜或停)、数据抓取(决定刷哪些作品/何时停/失败重试)、素材抓取(找→评估→再找)。现状:调研走 material.gather 单发模板(无真正循环);抓取走确定性 runner(`runScheduledCollection` dispatch→void runXxxTask,刻意确定性以防封号)——**决策层不智能**(刷哪些、够不够都是固定规则)。
- **环境感知缺口**:T-253 已给 local.read(读任意文件+确认卡),但没有目录列举/已装工具探测——编导不「知道」用户电脑里有什么。

## 2. 架构修正:三种循环,各归各位

> 修正此前「大脑用自研 harness=壁垒」的过度简化。壁垒是**领域知识+数据+确认门+防封端口**,不是「loop 一定要自己写」。自主循环的 loop 质量该外包就外包。

| 循环类型 | 归属 | 谁在场 | 例子 |
|---|---|---|---|
| **对话循环** | 自研 chat-runner | 人每轮在场 | 编导对话、稿面协作 |
| **自主任务循环** | **专门引擎(Pi/OpenCode)+ 注入领域工具/护栏** | 无人盯每步 | 选题调研、抓取决策、素材整理 |
| **确定性 runner** | 脚本 | — | 视频渲染、固定采集管线 |

**判定规则(一个任务落哪类)**:能写成确定脚本 → runner;有硬安全约束(封号/不可逆)且流程固定 → runner;**开放式、多步、需边做边判断、无固定终点 → 自主循环**。规则落成代码注释+SPEC 附录,防「什么都塞 agent」。

## 3. 核心设计:agent 决策,确定性端口执行

> 不能松的螺丝。一个 agent 在抖音页面自由发挥 = 封号 + 不可预测。受控通用手的正解:**引擎的自由限在「推理」,不在「raw 执行」。**

- **引擎负责「想」**:该抓哪个作品、够了没、失败怎么绕、下一步搜什么——多步决策与编排。
- **确定性端口负责「做」**:实际那次抓取/搜索/文件操作,**限流/防封/登录态/幂等全烤在端口里**(复用现有 ingestion 端口、web 采集端口、local.read)。agent 拿到的是**领域工具**(「刷新这批作品指标」「搜这个话题」「读这个目录」),**不是 raw 浏览器/raw shell**。
- **对三例的落法**:
  - 选题调研(web 搜+读+综合):最纯自主循环、安全风险低 → 引擎放开跑,工具=web 搜索端口+web.read 分窗(T-251)+知识写入门。
  - 数据抓取:引擎决策「刷哪些/何时停/错误重试」,真正抓取走 ingestion 确定性端口(封号纪律在端口)。
  - 素材抓取:决策层给引擎,落地抓取给端口。

## 4. 控制模型(护栏,复用今日已建)

> 复用锚:T-253 local.read 确认卡+denylist、T-255a 执行沙箱+执行结果确认卡+abort/超时+ai_task 步骤流、chat-tool-gate 工具门(T-239a)、honesty 条款、live dispatch 范式、multimodal model-config 可配。

1. **每任务工具白名单**:自主任务声明可用领域工具子集(调研任务给不了抓取工具,反之亦然)——复用 SURFACE_TOOL_SCOPES 思路(T-240)。
2. **步数/预算硬顶**:max steps + token 预算,到顶诚实终止(不无限绕圈)——自主循环无人盯,这条比对话时更关键。
3. **检查点+可续跑**:长任务分步落 AITaskStep,中断/超时可续(T-207 sweep 兜底已在)。
4. **干跑预览**:副作用前先产计划给人过目。[gate-m2] 形态分两类——**发布/删除类强制**(渲染类沿用 T-254 确认卡);**搜索/抓取类默认不强制**(过程可续可停,产物过采纳门即可),需要时预告「计划搜的词/抓的作品范围」。
5. **副作用确认门**:落库/发布/删除走既有确认卡(铁律②:采纳才生效)。
6. **限流防封**:抓取端口内建速率限制+登录态复用,agent 无法绕过(它调端口,端口自限)。
7. **abort 贯通**:用户可随时停,信号贯通到引擎子进程/循环(T-239c 模式)。

## 5. 环境感知扩展(A 型,确定性,低风险)

- **目录列举 = 复用 T-253 已交付,不新建**[gate-M3]:`LocalReadToolResult.listing` 已返回 `entries:{name,kind:file|dir,size}+total`(chat-tools.ts:762,denylist+路径防护+确认卡俱全)。本 SPEC **不重造**,自主任务领域工具直接调它。
- **工具探测(本 SPEC 唯一新增感知能力)**:探测系统已装工具(ffmpeg/node/python/git 等 `which`),让编导「知道」环境能力、诚实引导缺失项(video.render 已有 ffmpeg 探测先例 T-254a)。
- **项目工作区感知**:编导可读当前项目关联的本地素材目录清单(经确认卡授权目录后)。
- **边界**:感知=读+列,不含 raw 写/执行;写与执行仍走确定性端口/确认门。

## 6. 引擎选型(承接 T-255b 实测)

- 自主循环运行时 = **Pi**(earendil-works/pi,MIT/库级嵌入最轻/默认4工具契合白名单)——**用户 2026-07-12 拍板直接选定,不做 Pi/OpenCode 实测,T-256d 关闭**。OpenCode/goose 为备选记录在案。**C 案整壳否决不变**。Pi LLM 回接 model-config(§6.1);NOTICE(MIT)进关于页。
- 集成形状 = T-255a 执行层的 executor 一种(agentic executor):dispatch/沙箱/确认卡/步骤流零改动;引擎注入我方领域工具适配器(把领域端口包成引擎认的 tool 接口)。
- NOTICE/许可义务进 app「关于/开源许可」页(gate-F1 处置沿用)。

## 6.1 引擎 LLM 调用回接 model-config(宪法铁律1/4 处置)[gate-M1]

> reviewer 逮到的宪法级张力:Pi/OpenCode 自带 model client + 自由文本循环,与宪法 §9 铁律1「全程 Vercel AI SDK / modelFor」+ 铁律4「每轮 schema 约束」正面冲突。处置:

- **引擎每步推理必须回接 model-config**:优先选「引擎支持自定义 OpenAI-compatible endpoint」的引擎(Pi/OpenCode 均可配 base_url+key),把它指向由 `modelFor`/`resolveLlmConfig` 解析出的用户 provider——引擎的自由循环仍然烧的是用户配的模型,不引入第二套模型解析。**若某引擎无法回接(硬绑自家 provider)→ 该引擎淘汰**(这是 T-256d 选型硬门,不是可选项)。
- **铁律4 边界厘清**:铁律4「每轮 generateObject schema 约束」约束的是**产物入库那一跳**(确认门前的结构化产物,如调研产出的候选/卡片仍走 runStructuredNode)。**循环内的中间推理**(该搜什么、够不够)是自由文本决策,**显式豁免** schema 约束——理由:自主循环的价值恰在自由决策,强套 schema 就退化回单发模板(等于没引擎)。豁免仅限「不落库的中间步」;任何**落库/副作用**产物仍受铁律4+确认门双管。
- **不用 Claude Agent SDK**:Pi/OpenCode 均非 Claude Agent SDK(MIT 开源引擎),铁律1「不用 Claude Agent SDK」不违背;新增的是「受控第三方 agent 循环」,与「对话主链全程 Vercel AI SDK」并存(对话循环不动,§7)。

## 7. 边界(防走样)

- **对话循环不动**:领域知识/场景/诚实/工具门留自研 chat-runner,不外包(壁垒)。
- **引擎自由限在推理**:副作用只经确定性端口+确认门;raw 浏览器/shell 不暴露给引擎。
- **不是所有任务毕业成自主循环**:判定规则挡住「什么都塞 agent」。
- **模型现实**:MiniMax 弱模型自主循环风险最高 → 步数/预算硬顶+检查点+干跑预览是必需不是可选。
- 模型全走 model-config 用户可配。

## 9. 验收

- 环境感知:编导能列目录/报已装工具/诚实报缺失,越权/敏感文件被 denylist 挡。
- 自主循环:一次真选题调研(MiniMax)——编导多步搜+读+判断够不够+综合成候选,步数到顶诚实停,中断可续,产物过确认门入库。
- 封号纪律:抓取类自主任务,实际抓取走限流端口,agent 无法绕过速率限制。
- 干跑预览:高风险任务先出计划给人过目。
- 三端 typecheck+单测(工具白名单/步数硬顶/检查点续跑/领域工具适配器/判定规则纯函数);引擎接入归真机验(真循环一条)。
