# T-904 官方受管生图提交断连恢复 SPEC

> 日期：2026-08-20
> 状态：用户要求继续处理；复用 T-735、T-891 的计费幂等与瞬时拒绝恢复契约

## 1. 真实问题

CreatorOS 1.1.0 本机加密日志中，`cover.brief` 均成功，但三次 `cover.generate` 与四次
`asset.generate` 在真正提交生图请求约 5 秒后统一取消：`reason=network`、`stage=submit`、
`retryable=false`、`生图任务提交结果未知`。约十分钟后同一链路在 47 秒内成功产出封面候选，证明
配置、模型、封面提示词与响应解析并未永久损坏，首个公共故障是瞬时提交连接中断。

现有 T-891 只恢复上游明确返回 408/429/5xx 的请求。网络层没有 HTTP 响应时，OpenAI-compatible
适配器统一丢弃原始异常并标为不可重试，导致官方受管网关即使已经承诺识别 `Idempotency-Key`，也
无法使用同一个幂等号恢复。

## 2. 已确认行为

- 官方受管模型：提交阶段发生 `network` 且结果未知时，沿用原任务、原封面方案和同一
  `Idempotency-Key`，最多按既有 1 秒、3 秒节奏再试两次。
- 用户自配模型：网络提交结果未知时仍立即停止；除非上游明确返回可重试 HTTP 状态，否则不得自动
  重放，避免不支持幂等的中转站重复计费。
- 明确 408/425/429/5xx 的既有恢复策略不变。
- 每次自动恢复都不得重新生成封面方案、创建第二个任务或形成多个候选；最终只允许一份候选。
- 失败日志保留稳定的阶段、原因和重试决策，不记录 Key、完整 URL、上游正文或供应商内部信息。

## 3. 边界

这是网络/幂等可靠性策略，不参与提示词、封面创作或模型选择。

`SEMANTIC_BOUNDARY_ALLOW:` 确定性代码只按已验签的 `displayModelKey=channel-managed`、错误阶段、
错误原因和真实幂等号决定是否安全重放，不做任何内容语义判断。

不新增数据库、公共 operation、设置项或用户数据写入；不调用真实计费接口做自动测试。

## 4. 验收

1. 红测复现官方受管封面第一次 `network/submit/retryable=false`、第二次成功；证明同一封面方案只生成
   一次、同一幂等号使用两次、最终仅一份候选。
2. 普通图片素材覆盖同形断连；官方受管链有界恢复，用户自配链只调用一次并诚实取消。
3. 已有 502/503 回归、提交响应未知检查点、防重复计费与本地落盘恢复测试保持通过。
4. 运行 cover、asset、OpenAI-compatible adapter 聚焦回归、TypeScript、boundary、semantic 与
   reconcile；不把最新一次偶然成功冒充稳定性修复证据。
