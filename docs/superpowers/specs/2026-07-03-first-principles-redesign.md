## §0 第一性诊断:什么老旧、什么不老旧

**不老旧(资产,不动)**:宪法的定位与原则全部成立——编导智能体、飞轮复利、确认门、编导对话化、七步流水线、数据底座。数据模型、contract ops、backend 模块、AI 节点体系全是资产。

**老旧的是实现层骨架**:宪法 §6 说「AI 功能统一成上下文感知的 ChatBox」,§5 说「人只审/改/删」,但 IA 是 **11 项一级导航的 MCN 部门结构**(首页/定位/选题/校准/项目/知识库/素材/发布/任务/经验/设置)。这是把一个团队的组织架构表搬给了一个人。审计证据:

- **一条作品的生命周期横跨 6 个一级页面**(选题 /topics → 立项 /projects → 稿面 → 制作 → 发布 /publishing → 复盘),用户在部门间跑腿。
- **多数页面看多干少**:素材中心 80% 看、项目列表 60% 看、首页是纯导航枢纽(6 卡全是去别处的路标)。真正的「干面」只有四个:稿面(创作)、选题池(决策)、经验裁决台(学习)、各倾倒场(录入)。
- **用户自己的裁决轨迹已经指向答案**:T-055 稿面=项目单一主视图;T-060 全部 AI 交互收敛对话+确认门、禁 agent 弹窗;T-060③/T-062c 倾倒场「倒进去自动归类」;T-062a 裁决台;T-059 全功能 CLI 化。每一批反馈都在把「页面部门」推向「对话+少数工作面」。

**第一性推导**:单人创作者的核心资源是时间与注意力。系统价值 = 降低决策成本(今天做什么)+ 降低生产成本(稿/素材)+ 复利学习(下一条更准)。因此系统骨架应该回答三个问题——「**今天干什么**」(行动)、「**东西在哪做**」(工作面)、「**攒下了什么**」(资产)——加一条随时候命的编导对话。部门式导航回答的是「功能在哪」,那是软件本位,不是创作者本位。

**对话主干**:Copilot 全局 ⌘K + 稿面常驻右栏(已有);一切 AI 能力 = 工具卡 + 确认门(已成型);T-059 吸收为底座切片(contract ops → MCP server,外部 AI 可调)。

**降级判定逐页**(证据见审计):

- **topics → 作品页「候选」tab**:选题不是独立部门,是作品的胚胎。作品页变成「候选 → 进行中 → 已发布」全生命周期漏斗——立项 = 候选卡换 tab,不再跨页。出题已全部走对话(T-060①),AI 选题会带随迁。
- **publishing/calendar → 作品页「已发布/排期」tab**:发布中心的表现列表本来就是「已发布的作品列表」;排期是作品的时间视图。发布操作流(T-055h 残留)落在稿面发布包区。
- **positioning → 设置页签 + 对话**:定位生成/进化已是对话工具(T-058 positioning.generate + 采纳卡);页面剩余价值 = 查看/手改当前定位与版本链 = 设置形态。选题/脚本消费定位走 creative-context,不需要页面。
- **calibration → 项目内 + 设置页签**:盲预测发生在发布前(稿面)、对照发生在复盘(项目内)——校准的消费场景全在作品生命周期里,不是独立部门;rubric/规则建议裁决放设置「校准规则」页签(T-062a 回流的建议在这采纳)。
- **automations/accounts → 设置页签**:调度配置与账号绑定,纯配置形态(accounts 的绑定卡设置页已有)。
- **experience/knowledge/assets → /library 三 tab**:三者同为「资产」,同一倾倒场心智(素材倾倒/知识倾倒/经验裁决),搜索共用。现有三页的内容组件整体复用,只换壳。
- **search**:保留(header 全局搜索着陆页,非一级导航项)。

## §2 宪法修正案 §11(过审后写入 docs/产品定位.md)

> **§11 信息架构(2026-07-03 修正案)**:一级导航固定为**今日台 / 作品 / 库 / 设置**四项 + 全局编导对话(⌘K / 稿面常驻)。任何新能力先问三个归属:是「行动」(进今日台队列)、是「工作面」(进作品生命周期或库 tab)、还是「配置」(进设置页签)——**禁止新增部门式一级中心**。页面存在的理由是「干」,只读仪表信息并入所属工作面,不单独立页。
