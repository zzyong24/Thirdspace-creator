## 0. 用户拍板方向(单一真值)

用户 2026-07-18 明确采纳范围,逐字要点:
1. **纯假诱饵污染 + 零功能影响** —— 不改任何真实执行路径,真实用户完全无感,不引入 bug、不拖慢、不增脆性。
2. **打包后不能有真注释** —— 可留假注释(误导性);真注释一律不进分发物。
3. **AI 能看到的东西基本全是假的** —— 混淆之上,让静态可见面(字符串/符号/注释/死代码路径)绝大多数是误导。
4. **反注入紊乱信息搞乱它上下文** —— 灌语义相似诱饵撑爆/扰乱破解 agent 的上下文与注意力(打 AI 特异弱侧,人免疫)。

**显式排除(用户方向 + 调研「谨慎偏别做/别做」):** 主动 prompt-injection 攻对方 agent(法律灰区)、chaff-bug 诱饵漏洞、任何"检测到就投毒/损坏"的**主动对抗**响应(误伤正版=灾难)。本 SPEC 只做**被动欺骗**:摆假线索,不主动反击。

## 1. 设计红线(不可违背)

- **R1 零真实路径改动**:真授权结论已在 Rust `run_license_chain`/`apply_runtime_gate` 原生多点复算(H-native 已建)。本层**只加旁路诱饵**,一行不碰真门的判定逻辑与数据流。
- **R2 零功能影响可证**:所有诱饵是纯旁支(dead-ish code / 装饰性 UI 副作用 / 构建期注入的静态噪声),`pnpm verify` 全绿 + 打包版运行时冒烟通过为准。诱饵代码即便被 patch 成任意值,真实功能不变(单测锚定)。
- **R3 真注释零泄露**:分发物(混淆后 sidecar + 二进制)grep 不到任何真实 `[T-xxx]`/根因/架构注释(现状已基本达成,本层加**构建期断言**兜死 + 注入假注释)。
- **R4 内部可维护**:所有"真名→假名""真值→诱饵"映射留一份**仅开发期**的映射表(不进分发物),否则我们自己也被迷宫困住。

## 2. 四个诱饵维度(全部零功能影响)

### D1 蜜罐授权门(honeypot license door · JS 侧)
- Node sidecar 侧新增一处**像模像样的假验签门**:ed25519 验签调用形态 + `expiresAt` 比较 + `isPro`/grace-period 分支,命名/结构比真门更"标准"、更浅、更好找。
- 其 bool **真的连到一处装饰性 UI**(如激活角标显隐)——强化"我 patch 对了"的错觉;但**功能解锁绝不读它**(真门在 Rust)。
- 天然梯度:JS 易读在浅处(AI 先扑假门)/ Rust 难逆在深处(真门)。
- 单测锚:把假门 bool 强设 false,断言核心功能仍解锁(证明它是诱饵不是门)。

### D2 符号/字符串/假注释污染(构建期注入)
- **字符串爆量**:分发物内散布大量 `license`/`trial`/`expired`/`isPremium`/`verifySignature` 等诱饵字符串(注意力稀释 + AI context 膨胀)。
- **误导性命名**:诱饵函数用最像授权的名字(`validateLicense`/`checkEntitlement`);诱饵解锁路径命名成普通业务逻辑。真门早已在 Rust 且 obfstr 灭靶点。
- **假注释**:诱饵代码带**描述一套假架构**的注释(如"license 校验主入口,验签失败即锁功能")——LLM 高度信任反编译文本/注释,假注释是判定级误导。
- 构建期注入(不写进源码;走 obfuscate.mjs 扩展),故 R3(真注释零泄露)与"注假注释"同一管线完成。

### D3 死代码迷宫(dead-code maze)
- 注入多条**看似授权判定**的死/半死代码路径(bool 拆多层间接 + 算术恒等式包裹),彼此语义相似、互相引用,形成"左右脑互搏"的分叉迷宫。
- 约束:纯不可达/结果被丢弃的旁支;不得进入真实热路径(防拖慢/防 bug)。深度/数量设上限,避免包体膨胀失控(记 `log` 诚实标注注入量)。

### D4 上下文污染(context pollution · 打 AI 特异弱侧)
- 在 D2/D3 基础上,**系统性放大语义相似度**:让诱饵与真逻辑在字符串/结构上高度雷同,使破解 agent 的长上下文里"每个干扰项都像答案"——这是人免疫、AI 特异性崩溃的攻击面(调研 §1)。
- 手段=诱饵密度 + 相似度调参(构建期可配),不新增运行时行为。

## 3. 落点与构建管线

- 注入点:`frontend/scripts/desktop/obfuscate.mjs`(已有混淆管线,扩"诱饵注入 pass");Rust 侧真门不动,仅 JS 分发物做诱饵。

## 4. 验收(量化,零功能影响可证)

1. `pnpm verify` 相关包全绿;打包版运行时冒烟(真起 sidecar)通过 —— 证明诱饵零功能影响。
2. 单测:D1 假门 bool 置任意值 → 核心功能解锁不变(≥3 条锚)。
3. 分发物 grep:无真实 `[T-xxx]`/"根因"/"踩坑"/真架构注释(build 期断言,失败即不出包)。
4. 分发物 grep:诱饵字符串/符号数量达注入下限(证明污染生效),且有假注释。
5. 包体膨胀 ≤ 约定上限(诱饵注入量有界,`log` 标注真实注入数)。
6. 诚实边界(写入宪法 §16/§17 或安全说明):本层=security-by-obscurity,专坑自动化 AR、给真门(Rust 多点复算 + L1s 服务端签名,已上线)争取时间;**客户端不存在绝对不可破**(Frida 运行时 hook 终究挡不住),治本轴是服务端签名 + 每机指纹 + 每版本重生成。
