# T-687 口播联想画面 Skill 与素材进成片闭环

> 用户确认（2026-08-04）：文生图素材不能只做泛化配图，应结合口播内容生成能帮助观众理解、
> 联想和记忆的画面；这套编导判断应收敛成 Skill。现有项目素材必须真实进入视频，且对话中的
> `image2` / `图2` / `第二张` 必须能指向刚生成的真实候选。

## 1. 一句话定义

不另建第二套视频管线：`video.broll` 以口播稿为语义真源，只产画面槽位；现有
`material.match` 读取口播、场景、画面槽位与项目真实素材清单，由 AI 完成素材语义匹配。代码只做
真实 assetId、归属、场景索引和时间边界校验，禁止用写死词表或字符串相似度代替 AI 选素材。
没有合适素材时保留可生成的视觉方案与人工指定入口。用户采纳生成候选后，素材经现有
`material_links` 绑定项目，再重跑同一 `video.decisions → video.render` 主链。

## 2. AS-IS 证据

### 2.1 本机日志（2026-08-04）

- 13:56:56 同一项目连续发起 4 个 `material.generate`。
- 13:56:58–13:57:24 已开始 `video.scenes / video.cards / video.broll`。
- `video.broll` 只输出 12 tokens，随后视频决策仍完成。
- 13:57:38–13:57:58 四张生成图才陆续进入 `awaiting_confirmation`；此时尚未采纳入项目素材。
- 14:00:43–14:00:50 渲染仍成功，说明当前链路允许在 B-roll 为空时静默生成无素材成片。

### 2.2 源码证据

1. `context.materials` 只按已入库素材标题查询；未采纳的生成候选不在素材库中。
2. 生成卡没有稳定别名，也没有把 `图1 / 图2` 等别名写回对话上下文；`image2` 无法确定解析。
3. `material.generate` 接受裸 prompt，不读取口播语义、段落作用、目标观众和视觉功能，因此容易产
   出通用图库感画面。
4. `video.broll` 同时规划画面并挑素材，职责混杂；独立 `material.match` 未接入视频分场主链。
5. 渲染器会严格物化已经写进 `renderProps.broll` 的素材，但上游若得到空 B-roll，渲染器仍会正常
   出片，所以“素材没进入成片”的主要断点在候选时序、项目绑定和决策重跑，而不是模板忽略文件。

## 3. 产品交互

### 3.1 画面计划

口播定稿后，Skill 按语义节拍生成 3–8 个画面槽位（按真实内容密度，不硬凑数量）。每个槽位展示：

- 对应口播片段；
- 画面作用：`事实证据 / 类比联想 / 过程示意 / 对比反差 / 情绪氛围 / 信息卡`；
- 画面建议和“为什么用它”；
- 当前状态：已匹配素材、缺素材、生成候选待采纳；
- 已匹配真实素材或「生成缺失画面」动作。

不直接为每段批量烧模型费用。默认先产计划和复用已有素材，用户对缺口执行“一键生成”；生成结果
仍走候选卡，用户采纳后才进入项目。

### 3.2 对话别名

同一轮生成的卡片按可见顺序标为 `图1 / 图2 / 图3…`，同时支持：

- `image2`、`img2`、`图2`、`第二张`；
- `刚才第二张`、`刚才那组第二张`；
- 直接点击卡片产生的真实引用。

别名只在当前会话与当前生成批次内解析，解析结果必须是 `taskId + candidateId/assetId`；批次不明确
或候选已删除时要求用户确认，禁止靠标题模糊猜测。采纳后别名继续指向同一真实 `assetId`。

### 3.3 进入成片

1. 生成候选；
2. 用户采纳；
3. backend 将 asset 从 pending 提交为 active，并绑定当前项目 `role=broll, stage=production`；
4. 制作页立即刷新项目素材，不要求用户退出重进；
5. 已存在旧视频决策时显示“素材有更新，需要重新配画”，不得静默复用旧快照；
6. 重跑 `video.decisions` 后，确认卡明确列出每条 B-roll 使用的真实素材；
7. 渲染前校验选择的每个 asset 都已进入 execution inputs；缺失则阻断并指出是哪一条，禁止静默出片。

## 4. Skill 契约

沿用并协作两个 official Skill，不新增平行渲染器：`video.broll` 输出画面需求，
`material.match` 输出真实素材到场景的 AI 匹配结果：

```json
{
  "slots": [
    {
      "sceneIdx": 0,
      "narration": "对应口播摘要",
      "purpose": "analogy",
      "visualConcept": "观众看见的具体画面",
      "reason": "它如何帮助理解这一句",
      "generationPrompt": "只描述画面，不复述口播文字",
      "at": 3.2,
      "durationSec": 3
    }
  ],
  "broll": []
}
```

`material.match` 在视频模式下返回 `assetId / sceneIdx / at / durationSec / reason / presentation`；其中
`assetId` 必须来自当前项目清单，场景与时间由动态 schema 校验。

约束：

- 素材语义选择只由 `material.match` 完成；`video.broll` 和确定性代码不得再次猜素材。
- `generationPrompt` 只在缺素材时提供，必须把抽象主张转为具体人物、动作、空间、物件或关系。
- 默认不在图片上塞文字；需要文字表达时转为 `video.cards` 信息卡，不让生图模型画乱码。
- 禁止“商务人士看电脑、发光大脑、机器人握手”等与任何稿子都能套用的通用 AI 图。
- 事实性内容优先真实截图/资料；AI 图只用于联想、示意和氛围，不冒充新闻证据。
- 一个语义节拍只安排一个强视觉，避免卡片、B-roll 和字幕互相打架。
- `presentation` 由 AI 在 `full_frame / large_stage / overlay` 中选择：需要阅读文字或观察操作的界面截图/录屏只能使用前两种，持续操作必须给足可读时长；代码不得按文件名或行业词表猜呈现方式。
- 渲染器对 AI 结果施加物理可读性下限：旧候选缺字段时按 `large_stage`，`full_frame/large_stage` 始终 `contain` 且占据画布主要区域；这属于播放器可读性，不替代 AI 的素材与构图语义判断。

## 5. 确定性代码边界

以下不能写进提示词后假装完成，必须由代码与契约保证：

- 生成批次与 `图N/imageN` 别名表；
- 候选采纳后 project material link 的原子写入与幂等；
- 制作页素材刷新、旧决策失效提示；
- `assetId → execution input → sandbox file → renderProps` 完整校验；
- 已选 B-roll 未进入最终 HTML/渲染步骤时的显式失败与日志；
- 日志记录 inventory 数、选中数、缺口数、生成数、采纳数、渲染实际使用数。

## 6. 测试与 Gate

按 Skill 编写规则先写失败基线，再改 Skill：

1. **自然语言路由基线**：给出含 4 张候选的会话，输入“用 image2”，当前实现不能解析；修复后必须
   唯一解析到第二张，跨批次歧义必须拒绝猜测。
2. **画面质量基线**：至少 3 条不同口播（事实、抽象方法、情绪故事），现有裸 prompt 产出通用图；
   新 Skill 必须给出不同画面作用和可拍/可生成的具体视觉概念。
3. **项目绑定集成测试**：项目态 `material.generate → awaiting_confirmation → confirm` 后，
   `listBrollInventory` 必须读取到同一 asset，且只出现一次。
4. **时序回归**：决策开始时仍待采纳的候选不得伪装为可用素材；采纳后旧决策必须标过期并可一键重跑。
5. **渲染闭环测试**：决策选择的每个素材都必须出现在 `buildRenderInputs`，缺一项渲染必须失败；
   真机成片抽查选中素材在对应时段可见。
6. **Skill 质量评估**：先用旧 Skill 记录失败表现，再运行新 Skill；不补拍历史 PASS。

## 7. 不做

- 不让 AI 未经用户采纳直接写素材库。
- 不把 `image2` 继续解释为标题搜索词。
- 不在视频渲染阶段临时自由发明新画面。
- 不新增第二套素材表、第二套视频决策或第二个渲染器。
