# T-920 业务 Skill 执行方法补齐

用户明确要求把类似素材研究的业务执行方法全部放入现有 Skill 管理，复用 T-915 运行时与当前工具/输出契约；不新增第二套 Skill 配置中心。

## 实现与范围

在 ai-worker 官方模板注册层为所有现有业务 Skill 补齐目标、输入使用、执行方法、失败处理和交付自检。按注册 ID 显式绑定业务方法，不按用户关键词确定语义；对话类 Skill 包含通用方法目录，由模型根据当前意图选择。结构化节点只加载对应职责的方法，不要求无工具节点调用工具。现有账号 Skill 覆盖和冻结快照继续生效；设置页展示、编辑的 system 与运行时正式读取同源，不增加不可编辑的隐藏执行文本。

素材研究：先使用全文拆解证据/案例/视觉需求，再形成精确检索问题、阅读来源并判相关性；无关结果不等于完成，自主调整；最终说明来源、支撑点、文案位置、用途和限制。其他覆盖定位、选题/热点、策划、稿件/改写、视觉/制作、发布适配、复盘/对标、知识/归因/分类以及产品帮助。用户当前意图优先，不自动续做已被替换的旧意图。没有关键歧义时不反复确认。

Loop 只提供行动机制，Skill 提供方法；代码守权限、幂等、预算和输出类型。不得增加审美 fail-closed 门或伪造业务完成。保留有效部分与真实缺口，不以补齐 Skill 宣称所有模型任务已验收。

## 验证与交付边界

检查注册覆盖、设置读取与快照调用链以及类型编译。用户此前要求暂缓业务自动测试，继续遵守；真实模型效果、性能与本地安装包另记待验证。更新现有官方基座不覆盖用户已定制的 system，旧任务冻结快照保持旧版本。

流程：用户意图 → 已管理 Skill 的方法 → 可用工具/输入 → 产物与自检 → 结果或真实阻塞。

## 运行入口补充

盘点发现 exec.agentic.research/material/collect 三个独立 Pi 入口仍只有固定 system。为其登记同名官方业务 Skill（仅开放 system 编辑，避免无效工具/模板编辑），新任务准备时解析当前账号的有效 Skill，将 methodSystem 冻结到原 modelInput.systemPrompt；已绑定执行任务直接回读旧输入，不重新读取配置。既有执行预算、工具授权和候选边界保留。原 45 个 Skill 加这 3 个共 48 个。

独立评审：skill_method_review 对官方注册→账号覆盖→冻结快照方案评审通过；重复注册须幂等，用户自定义不被覆盖，无工具节点不得扩大权限。真实模型与 UI 验收未执行。
