> 状态:设计/梳理稿。基于一次只读代码盘点(项目/知识库/素材中心)+ 飞轮工作流再梳理。
> 配套:数据源采集管线见 `2026-06-30-data-source-pipeline-design.md`(经验沉淀依赖它提供"真实结果")。

## 0. 一句话结论

产品比预期更真、更诚实(盘点:32+ 真 / 6 假 / 5 半,多数占位老实标了"规划中")。**真正会误导用户的假按钮只有 3-4 个,半天可清。** 战略缺口是**经验沉淀这条飞轮闭环**还没接通,而它依赖刚设计的采集管线。

## 1. 真实业务工作流(飞轮)+ 当前接通状态

```
定位(谁/做什么/差异化)──约束─┐                    [✅ 真:定位中心已落库]
                              ↓
   ┌──回流──→ 选题(候选池) ←── 数据源:评论/对标/热点/知识/复盘
   │            ↓ 立项          [✅ 选题真;⚠️ 数据源 4真3假(对标/热点假),basis 装配有 bug]
   │         Brief(选题→项目)   [✅ 真:立项工作台 + 必填门]
   │            ↓
   │         脚本(分镜/草稿) ←── 知识库 + 素材中心 喂料   [✅ 脚本真;知识库真;素材读真]
   │            ↓
   │         制作(素材匹配/用料链)  [⚠️ 半:模式切换真,但剪辑/预览/导出 规划中或假]
   │            ↓
   │         发布(一稿多平台)+ 盲预测  [✅ 发布配置/时间表真;校准盲预测真]
   │            ↓
   │      [采集管线抓真实表现]   [❌ 缺:这一环没做 = 飞轮断点]
   │            ↓
   └── 经验沉淀(复盘:对照+AI诊断→learnings) ←闭环  [⚠️ learnings 表有,但链路没接通]
```

**结论:飞轮的"前半段"(定位→选题→Brief→脚本→发布)基本通;"后半段"闭环(采集真实表现 → 复盘 → 沉淀 → 回流)是断的。** 这是最该补的战略缺口,不是零散假按钮。

`变现中心`:**移除**(用户决定,太难且不影响飞轮)。导航去入口 + 路由/模块隐藏 + 七步摘掉 `monetization`。

## 2. 经验沉淀链路设计(飞轮闭环·重点)

之前难设计,是因为缺"作品发布后的真实表现"——正是采集管线要提供的。链路:

1. **发布**作品(一稿多平台),发布时校准中心记下**盲预测分**。
2. 过 N 天,**采集管线**抓回真实表现(播放/赞/评/完播 + TOP 评论)。← 依赖数据源 spec
3. **盲预测对照**:预测 vs 实际 → 误差即校准信号(cheat-on-content 方法论)。
4. **AI 复盘诊断**(一个 AI 任务,走统一弹窗+日志):读 选题/脚本/预测/实际/评论 → 产结构化复盘(什么有效/没效/假设验证/新观察)。
5. **沉淀成 Learning**(`learningsService` 已有):一条可复用规律 + 证据。例:「前3秒抛冲突 → 完播率+30%(证据:作品X)」,validationStatus: hypothesis→validated。
6. **回流**:learnings → 选题(复盘源)/ 校准(更新 rubric)/ 脚本(参考有效结构)/ 定位(微调)。

缺的连接组织:②真实结果(采集管线)、④AI 复盘诊断、⑥回流接线。大头(learnings 表、校准盲预测)已有。

## 3. 统一 AI 交互规范(横切·杠杆最大)

**所有 AI 功能必须满足四条**(底座已在选题落地:`ai_tasks`/`ai_task_steps`/pending 指针/步骤日志弹窗):

1. 点一下 → **弹窗 + 实时步骤日志**(不是干转圈)。
2. **后台真跑**(任务持久化在 `ai_tasks`,fire-and-forget)。
3. **关弹窗不杀任务**,它继续跑。
4. **重开能看进度/结果**(pending 指针重读,不重复调 AI)。

落地 = 抽复用件 `useAiTask` / `<AiTaskDialog>`,把 校准诊断 / 脚本草稿 / 素材搜集 / copilot / 复盘诊断 全统一过去。一次抽象,全产品 AI 都"可观测+不卡死+可续"。**这同时治掉盘点里多处"点了卡死"。**

## 4. 功能 triage(盘点结果 → 处置建议)

### 立即清理(便宜·去误导,半天级)
| 功能 | 文件 | 现状 | 处置 |
|---|---|---|---|
| 制作:导出按钮 | production-interactive-region.tsx L1060+ | ❌ 纯本地 state,看着成功实没生成 | 禁用 + 标"规划中" |
| 制作:时间线章节 | L972 createSlot | ⚠️ 本地 state,刷新丢 | 标"规划中"或暂禁(别让用户白填) |
| 制作:AI 数字人卡 | L96-104 | ⚠️ disabled 无标签 | 加"规划中/敬请期待"标签 |
| 发布:评论区 | L1313 | ✅ 已标规划中 | 保持(已诚实) |

### 真做(按飞轮价值排,我的建议优先级)
1. **经验沉淀链路**(§2)——飞轮闭环,战略最高。依赖采集管线,和数据源 spec 一起推进。
2. **素材上传真存**——素材中心/制作的喂料起点;UI 全有,只差文件字节落 MinIO(P3 已建对象存储,接上即可)。成本中、收益高。
3. **统一 AI 交互规范**(§3)——横切,一次修一片"卡死"。
4. **数据源 4真3假补全 + basis bug**(对标/热点做真,见数据源 spec)。
5. **Copilot resume 锚定**——全局任务续到项目阶段,低成本中收益。

### 暂缓(高成本·诚实标规划中即可)
- 制作工作台的**真实剪辑(NLE)/ 实时预览(video codec)**——专业视频管线,成本极高。诚实标"规划中",不假装;等核心飞轮通了再评估要不要自研 or 接外部编辑器。
- 设备检测——纯前端,低成本,可顺手做但非关键路径。

## 5. 选题卡富录入项(S0,补全清单)

「新增选题卡」弹窗分组录入整张卡:
- 基本:标题\* · 切入角度
- 核心:一句话选题 · 目标观众 · 受众痛点 · 核心冲突 · 推荐 Hook
- 结构:内容结构 · 片长/格式 · 素材依据
- 立项:风险点 · 立项建议
- (评分:AI 补 / 系统算,不手填)

## 6. 排期建议(我的推荐顺序)

- **第 0 波(去误导 + 快赢,半天~1天)**:制作 3 个误导按钮标规划中/禁用 + 变现中心移除 + `Sfix` basis bug + `S0` 富录入弹窗。
- **第 1 波(横切·高杠杆)**:统一 AI 交互规范(`useAiTask`/`<AiTaskDialog>`)+ 把现有 AI 功能迁过去。
- **第 2 波(飞轮闭环)**:采集管线(数据源 spec D1-D7)+ 经验沉淀链路(§2)。
- **第 3 波(喂料补全)**:素材上传真存 + Copilot resume。
- **暂缓**:制作 NLE / 预览(诚实标规划中)。

## 7. 验收原则

- 每个按钮:真做 / 删 / 明确"规划中",无"点了看着成功实没做"。
- 飞轮后半段闭环:发布 → 采集真实表现 → 复盘 → learnings → 回流,端到端跑通一条。
- 所有 AI 功能符合 §3 四条规范。
