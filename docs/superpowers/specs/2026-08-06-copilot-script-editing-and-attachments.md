# T-716：Copilot 局部改稿、脚本版本回退、附件上下文与素材稳定排序

> 日期：2026-08-06
> 状态：BUILD 规格已确认（用户明确要求一次落地并生成本地测试包）
> 关联：T-691 Copilot 生命周期、T-712 视频制作编辑闭环、T-713 macOS 0.3.0 本地包

## 1. 用户问题

1. 素材中心同一批素材每次进入顺序不同，用户无法形成“最新素材在最前”的稳定预期。
2. Copilot 在稿面只能整稿重写，无法针对用户明确选中的段落提出修改。
3. 口播稿虽然每次保存都会生成版本，但稿面没有可发现的历史版本、预览与恢复入口。
4. 结构稿直接展示 `asset-...` 内部 ID，用户无法判断点名的到底是哪份素材。
5. Copilot 对话框不能像现代 AI 工作台一样拖入文档或图片作为本轮上下文。

## 2. 产品原则

- **局部修改是补丁，不是新整稿。** 用户从稿面选择段落后，Copilot 获得稳定段落锚点和该段原文，只产局部候选；只有用户确认后，系统才把候选合入当前完整稿，并追加一个新版本。
- **技术锚点由系统绑定，不向模型或用户索取。** `artifactId`、`versionId`、`sectionId` 和原文摘要来自用户点击时的可信稿面状态；模型只生成新的段落正文。模型不得要求用户手工提供 ID、再次选择段落或自行复制粘贴。
- **工具执行以当下数据为准。** 客户端和对话历史中的 ID、版本、正文与状态只表达用户意图；每次工具执行前必须按当前 RequestContext 从 backend service port 重读服务端真值。能唯一重绑则使用当前值，无法重绑则明确冲突，绝不拿旧快照继续。
- **恢复历史不制造版本。** 历史版本只读；“恢复”只把当前指针切换到已存在的历史版本，不复制、不覆盖、不新增。用户后续真正编辑并保存时才追加新版本。
- **素材使用用户语义。** UI 展示文件名/标题/缩略图，不暴露内部 assetId；失效素材显示“素材已失效”。ID 只作为后端校验与关联键。
- **附件显式、有限、可撤销。** 用户可拖拽或选择文件；上传、解析、识图状态清楚可见，可在发送前移除。数据库只保存附件资产 ID；文件内容和图片字节只在本轮推理内临时组装，禁止进入日志和普通缓存。
- **相同内容只存一份。** 上传完成后以服务端读取到的真实文件字节校验和为准，在同一用户、账号与素材类型范围复用既有素材；不能只靠文件名去重。不同账号之间不共享素材记录。
- **能力诚实。** 图片输入采用常见的拖入/粘贴输入区模式，[OpenAI 图片输入说明](https://help.openai.com/en/articles/8400551-image-inputs-for-chatgpt-faq)；支持视觉的模型读取图片，不支持时明确提示换用支持图片的模型。文档先做服务端安全提取，PDF 可包含文本、图片和表格，但需公开格式和大小限制。[Claude PDF 支持说明](https://docs.anthropic.com/en/docs/build-with-claude/pdf-support)
- **不新增第二套编辑器、版本库或上传系统。** 复用 artifact versions、项目素材上传链和现有 Copilot conversation/message attachments。

## 3. 交互与状态

### 3.1 素材中心

- 默认且唯一基础顺序：`createdAt DESC`。
- 相同 `createdAt` 时使用 `id ASC` 作为稳定次序，避免刷新或分页后抖动。
- 搜索、筛选、分页、回收站和恢复后都从同一排序函数派生。

### 3.2 定点改稿

- 结构稿每个段落提供“AI 改写本段”；富文本选区存在时提供“AI 改写选中内容”。
- 点击后先保存未落库编辑，再打开右侧 Copilot，并携带：稿件 artifactId、当前 versionId、段落/选区锚点、原文摘录。
- 上述技术字段只进入服务端可信工具闭包，不进入模型可填写的工具参数；即使模型回传伪造 ID 也无法覆盖可信锚点。
- Copilot 产出“原文 / 建议稿 / 修改说明”候选卡。
- 用户点击“采纳修改”时，后端重新读取最新版本并校验锚点或原文摘要；若已变化，拒绝覆盖并提示重新生成。
- 校验通过后只替换目标片段，并追加一个完整脚本版本；其它段落保持字节级不变。

### 3.3 版本下拉

- 稿面标题旁显示当前 `vN` 下拉。
- 列表按版本号倒序，展示版本号、时间、摘要和当前标识。
- 点击历史版本先预览；“恢复此版本”直接把该只读历史版本设为当前并刷新稿面，不新增版本。
- 当前版本不可重复恢复；操作具备 pending、成功、失败反馈。

### 3.4 点名素材

- 结构稿根据当前项目素材链接把 assetId 解析为文件名/标题。
- 显示素材类型和可选缩略信息；ID 不出现在用户可见文本。
- 找不到、越权或已删除时统一显示“素材已失效”。

### 3.5 Copilot 附件

- 输入区支持点击选择、拖拽和粘贴图片。
- 首期接受图片，以及 PDF、DOCX、TXT、MD；拒绝不支持格式并显示原因。
- 文件先进入既有资产上传链；项目内对话同时挂到项目素材，便于复用。
- 上传链完成时计算内容指纹；同一账号重复拖入完全相同的文件时复用原素材并合并输入区附件，不新增重复资产卡片。
- 发送请求只携带附件资产 ID；服务端按当前用户/账号/项目重新校验所有权。
- 文档提取为有边界标记的用户数据文本；图片以临时多模态 part 送入模型。原始字节、data URL 和提取全文不写入聊天文本或日志。
- 当前模型不支持图片时，不伪造识别结果，返回可理解的能力提示；文本附件仍可正常使用。
- PDF/DOCX 解析依赖必须进入桌面 sidecar 的真实运行时闭包；构建阶段对目标平台执行一次模块与原生绑定加载，避免“开发环境能读、安装包报错”。

## 4. 数据与安全边界

- 不改数据库表和数据归属。
- `ai_messages.attachments` 只保存已校验的资产 ID。
- AI 不直接写 artifact；候选经用户采纳后由 backend artifact service 追加版本。
- 附件内容视为不可信用户数据，必须包在 `<user_data>` / `<attachment_context>` 边界中，不得覆盖系统指令。
- 限制单轮附件数量、单文件大小和总提取字符数；越界在调用模型前拒绝。
- 所有 assetId、artifactId、versionId 必须在服务端按 RequestContext 校验，不能相信前端。

## 5. 验收

- 相同素材集合以任意输入顺序进入页面，输出均为 `createdAt DESC, id ASC`。
- 从指定结构段落发起 Copilot 后，候选明确指向该段；采纳只改变该段并新增版本，竞态时拒绝覆盖。
- 从稿面点击“AI 改写本段”时，即使存在未保存编辑也会先自动保存；整条链路不出现 `sectionId`、版本 ID 或“请手动改”的用户话术。
- 版本下拉可预览并恢复历史，恢复不新增版本且旧历史仍完整；恢复后下一次工具调用重读新的当前版本。
- 点名素材显示真实名称；缺失素材不泄漏裸 ID。
- 拖入图片/文档可见上传和解析状态；发送后消息保存附件 ID，模型临时上下文能读取内容；不支持视觉时有明确提示。
- 同账号重复上传相同内容只得到一个素材；跨账号相同字节仍保持隔离。桌面 sidecar 构建必须能真实加载 PDF/DOCX 解析依赖及目标平台原生绑定。
- 日志、HTML、数据库扫描不到图片 data URL、原始附件字节和附件提取全文。
- 相关单测、契约测试、边界 Gate、reconcile 通过；最后按 T-713 生成 CreatorOS 0.3.0 macOS 本地测试包并报告路径、大小和 SHA-256。

## 6. 架构判定

本任务不改变服务契约、表结构或数据归属：素材仍归 assets，项目挂载仍归 project material links，稿件与版本仍归 artifacts，Copilot 消息仍归 ai conversations/messages。新增字段均为现有接口的可选上下文和 UI 投影，因此进入 BUILD，无需新建平行系统或架构迁移。
