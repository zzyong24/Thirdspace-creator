# T-921 生成输出恢复

用户明确要求根治频繁中断、没有自动重试及非安全输出限制导致不可用。承接 T-915、T-646 和 T-900；本轮改共享结构化生成入口，覆盖调用此入口的全部业务 Skill，不新增运行时或队列。

## 行为与边界

已收到响应但 JSON 或 schema 不合时，先复用现有归一化，再把原输出、校验问题、实际 schema 带入节点级最多两次文本格式恢复。文本兼容模式同样恢复，不能在进入完整度修复前直接终止。原生协议失败后的文本降级作为第一次修复；仍不合时至多再修复一次。每次新请求仍经既有账本预留与结算，取消立即停止，未知回执、鉴权与外部错误不得被包装成格式错误或盲重发。

已有合法对象仅因 length 结束：有创作降级资格的输出保留，不能单凭终止原因丢弃可用候选；控制型输出保留完整性门与声明式修复上限。非安全辅助字段沿用已有 defaults/creative normalization，不补造事实。已完成拆解等阶段使用既有检查点。

图：模型响应 → 同次解析/归一化 → 不合则携原输出修复（有界） → 合法候选/真实失败；供应商未知回执 → 原恢复状态，不走格式修复。

## 验证

类型编译与独立代码审查；按用户授权暂缓业务自动测试、全局 reconcile 和真实模型验证，不据静态检查宣称根治验收。安装包未更新。日志若不能定位截图任务，明确无对应证据。

## 实现评审补充

独立评审 recovery_review 对上述方案 PASS。格式修复预算为整个节点共享 2 次，不能在完整度循环里重置；持久模型最多 1 + completionPolicy.repairAttempts + 2 次供应商调用。空改写正文允许在同一阶段追加 1 次生成，不重做拆解/选题；已结算响应后的 schema 和空正文错误独立分类。过滤响应不触发格式修复。用户确认依据为本轮明确要求与此前暂缓业务测试授权。
