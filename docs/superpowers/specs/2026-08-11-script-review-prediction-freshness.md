# T-767 改稿后审核与盲预测新鲜度收敛 SPEC

> 用户确认：2026-08-11 用户反馈“修改脚本后预测、审核都锁定，重新审核好几遍仍不能往下”。
> 范围：只修当前稿与历史审核/预测的版本新鲜度和状态同步，不改视觉布局，不新增审核或预测功能。

## 1. 问题与根因

当前稿面同时存在三份时间不同的事实：脚本不可变版本、审核报告、锁定盲预测。

1. `useLatestScriptReview` 只用首屏报告初始化本地 state；`router.refresh()` 带回新报告后没有同步
   新 props。同一脚本版本重新审核时，旧报告又不满足“版本过期”轮询条件，因此旧 block 可长期
   留在稿面和发布门，形成僵尸门禁。
2. 盲预测按 `content_output` 保存且锁定后不可改，这是历史事实的正确约束；但稿面没有比较预测
   `createdAt` 与当前脚本版本 `createdAt`。脚本改稿后仍把旧预测当作当前稿结果，永久显示“已锁定”。

## 2. 用户可见契约

```text
保存新脚本版本
  ├─ 旧审核：标为过期，不阻断；重新审核成功后所有审核/发布区自动换成新报告
  └─ 旧预测：保留历史，但当前稿显示“稿已改动”并提供“重新盲预测”
```

- 审核报告仍绑定真实 `artifactVersion`。新报告返回后，即使与旧报告属于同一脚本版本，只要报告
  `id` 更新，稿面审核卡、发布提示与登记门都必须同步更新。
- 旧报告的 block/risk 对更新后的脚本不生效；只有当前脚本版本的真实 block 才能硬拦登记。
- 锁定预测仍不可编辑、不可解锁、不可覆盖。若当前脚本版本创建时间晚于预测创建时间，则该预测
  只作为历史结果展示，当前稿允许创建并锁定一条新预测；最新的新鲜预测再次成为当前结果。
- 时间缺失或非法时不猜测过期；保持既有结果并允许用户查看。所有比较只使用服务端真实 ISO 时间。
- 不新增按钮位置、卡片、颜色、字号或布局；只复用既有入口并调整状态文案与可执行性。

## 3. 实现边界

- 复用 `PredictionResource.createdAt` 与现有脚本版本 `createdAt`，不新增表、迁移或远端接口。
- 稿面 VM 为预测补 `createdAt`，为当前脚本补真实 `currentVersionCreatedAt`；纯函数派生 prediction
  freshness，禁止改写历史 prediction。
- `useLatestScriptReview` 必须同步服务端新 props；审核任务完成后的 `router.refresh()` 是唯一
  跨区广播，不新增常驻全量轮询。
- 登记表单继续只读服务端刷新后的报告；过期报告保持既有软门规则，当前 block 才硬拦。

## 4. 验收

1. 当前版本 block 报告 → 同版本重新审核得到新 report id/pass → 审核卡和登记门解除旧 block。
2. 脚本 v1 锁定预测 → 保存 v2 → 原预测仍可查看但标为过期，出现“重新盲预测”；新预测锁定后
   恢复当前“已锁定”。
3. v1 block → 保存 v2 → 旧报告只提示需重审且不硬拦；v2 审核后切换新报告。
4. 刷新、切换 Tab 后状态一致；不删除审核报告、prediction、结果或用户脚本。
5. 前端聚焦测试、typecheck、build、boundary/orphan/test-integrity 与 reconcile 如实执行；不跑视觉校验。

## 5. 非目标

- 不改变盲预测的校准口径或不可变历史语义。
- 不取消真实当前 block 的发布硬门。
- 不修改审核模型、提示词、发布流水线或视觉。
