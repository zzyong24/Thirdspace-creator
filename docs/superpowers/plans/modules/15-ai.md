# Module 15 — AI — Executable TDD Plan (Wave 3)

> **For agentic workers:** REQUIRED SUB-SKILL `superpowers:test-driven-development` + `superpowers:executing-plans`. This plan follows the **keystone** conventions in `docs/superpowers/plans/2026-06-21-program-foundation.md` §5 (per-module template), §1 (module file layout, user-scoped repos, transport registry, `globalThis` pglite singleton), and §3 (real Claude Agent SDK). Steps use `- [ ]`. Each step is RED→GREEN; do not batch. Read the AI design spec `docs/superpowers/specs/2026-06-21-ai-orchestration-agent-sdk-design.md` before starting — it is authoritative for the worker/candidate-confirm boundary.

**Goal:** Wire the AI module end-to-end (FE button → contract op → user-scoped SQL → render) for the **AI Copilot** overlay (`/?copilot=open`) and the **AI 写作建议** adopt path in the **Script** workspace. Persist `AIConversation`/`AIMessage`/`AITask`/`AITaskReference`/`AITaskResult` and seed `AgentConfiguration`/`ModelConfiguration`. Make AI nodes **real** by promoting `@creatoros/ai-worker` Task 11 (a real `ClaudeAgentRunner` over `@anthropic-ai/claude-agent-sdk` + per-node Skills) reading the SAME pglite db through user-scoped read tools, writing an `AITaskResult` **candidate**, and stopping at `awaiting_confirmation`. The `采纳` button drives the AI-free `confirmResult` that formalizes the candidate into a new `ArtifactVersion` via the Artifacts module. Until `ANTHROPIC_API_KEY` is supplied, the worker runs the deterministic `FakeAgentRunner` stub so the chain is fully testable.

**Architecture:** Modular monolith under the Next app. New module dir `frontend/src/server/modules/ai/` per foundation §1 layout. The AI worker stays in its own package `ai-worker/` (foundation §3: cannot run in a Next request handler — the SDK spawns the Claude Code binary as a subprocess) and reads/writes the same `globalThis` pglite db via the shared infra db factory. Repository queries are **user-scoped only** (`eq(aiTable.userId, ctx.userId)`); child tables (`ai_messages`, `ai_task_references`, `ai_task_results`) are owned transitively through their parent (`conversationId`/`aiTaskId`) guarded by a `require*` ownership gate that filters on `ctx.userId`. Service takes `RequestContext`, implements the **AI Task** state machine (SPEC §12: `queued → running → awaiting_confirmation → completed`; `→ failed`; `queued/running → cancelled`). The candidate-confirm boundary (SPEC §18) is enforced: AI never writes a current ArtifactVersion directly — `confirmResult` is the AI-free formalize path that calls `ArtifactsService.createVersion(createdByType:"ai")`. Transport exposes the 6 contract ops below and is registered into the module registry; no edits to `compositeTransport`'s body — AI ops are added to `PERSISTED_OPS` via the registry union.

**Tech Stack:** TypeScript strict · Drizzle ORM over pglite (pure-WASM Postgres, `globalThis` singleton) · Zod DTOs re-exported from `@creatoros/contract` · Vitest (service unit, repository pglite-integration, contract-conformance) · `@creatoros/ai-worker` (existing: `state-machine.ts`, `orchestrator.ts`, `confirm.ts`, `candidate-schemas.ts`, `context-tools.ts`, `agent-config-resolver.ts`, `ports.ts` — 27 tests green) + new `ClaudeAgentRunner` over `@anthropic-ai/claude-agent-sdk`. Timestamps stored as ISO-8601 text (matches `iso8601` contract primitive), enums/status as text validated by the contract Zod on output — same conventions as the proven Projects slice (`backend/src/schema/projects.ts`, `backend/src/repositories/project-repository.ts`, `backend/src/persistence-transport.ts`).

**Dependency note (must be GREEN first):** Wave 0 (registry generalization + Identity/auth + mock adapters) → Wave 2 **Projects** + **Artifacts** (the confirm target — `confirmResult` calls `ArtifactsService.createVersion`; `AITaskReference` scopes resolve artifact versions via `ArtifactsService`) + **Knowledge** (knowledge-item references) → Wave 3 **Reviews** must land before AI (foundation §6: "Reviews unblocks `{Learnings, AI}`"). AI is the last node of Wave 3. The `@creatoros/ai-worker` foundation (Tasks 1–10) is already green; this plan adds Task 11 (real runner + Skills) and the persistence/transport/FE wiring around it.
