# CreatorOS 文案方法、板块权重与优化闭环调研

> 任务：T-790
> 日期：2026-08-12
> 状态：公开材料调研 + 仓内实现审计；已按用户最新裁决删除声音指纹方案，优化对象改为产品板块权重与工作流。
> 前置诊断：[CreatorOS 文案质量对标诊断](2026-08-12-copywriting-quality-benchmark-diagnosis.md)

## 一句话结论

CreatorOS 的“生搬硬套”不是缺一条更厉害的提示词，而是定位、素材、观点、结构、爆款公式、观众规则、对标方法、分镜和审核同时争夺文案控制权。正确的优化方式是：**一次固定一个主题，只产出文案；每轮微调一个板块或工作流参数，由用户先做 A/B 判断；积累跨主题偏好后，再让自动 loop 接管低风险实验，最终用证据调整产品各板块的优先级、输入预算和工作流位置。**

## 1. 外部调研的有效结论与边界

本轮只使用官方公开、用户提供或可核验材料。没有找到可核验的安先生或三把刀“内部 AI 提示词原版”；来源不明的网课下载、二手转售和所谓内部 prompt 不作为证据。

安先生公开内容强调：理解清楚，表达才会清楚；语言应解决具体需求；理想听众需要通过持续表达被创造出来。可核验公开来源包括[亲爱的安先生｜小宇宙](https://www.xiaoyuzhoufm.com/podcast/66ae009133ddcbb53c080105)和[抖音公开主页](https://www.douyin.com/user/MS4wLjABAAAAkzWHrOb9pgCBETkFM6RLp0GLDmfqrtz31YOJJrfHbAxH9gk3tGEEpke43cLZDgE-)。

用户提供的[《文案三把刀100条爆款文案实战手册》](https://docs.qq.com/doc/DQmxZSlRMb0F3Y2NV)显示：样稿的力量主要来自单一强主张、具体冲突、人物和动作、连续推进与自然收束，而不是“七步”名称本身。公开课程目录提到情绪选题、文字情绪渲染、标题和口语表达，但属于二手课程介绍，不能据此复原内部提示词：[《七步文案课》目录](https://www.waekk.com/xiezuo/1752.html)。

可迁移的是方法变量，不是老师语气：

- 主张强度；
- 冲突是否清楚；
- 事实/案例密度；
- 解释与演示的比例；
- 推进顺序；
- 结构约束强弱；
- CTA 与主张的连接方式。

这些变量都应进入可测参数面，而不是继续写进一条越来越长的系统 prompt。

## 2. 当前产品为什么容易套模板

### 2.1 `script.draft` 同时承担太多职责

当前 `script.draft v7` 直接产 `shots[]`，同时要求口播、画面、字幕、时长和视觉意图。模型在第一次成稿时就要兼顾观点、论证、口语、分镜和素材规划，连续说服过程被工程字段切碎。

### 2.2 同一篇稿有多个结构权威

一个生成请求可能同时包含 Project Brief、内容雷达策略、定位、经验、知识、素材、选题、论点、合同、结构方案和固定“钩子→痛点→价值→卡点→CTA”。模型最安全的做法是平均满足，于是每篇都像标准答案。

### 2.3 普适观众规则压过内容类型

当前共享条款要求“少论证、多断言+演示”。它对短演示可能有效，却会误伤观点、教程和案例。不同主题需要不同的解释/演示比例，这应该成为可实验的板块参数，而不是全局硬规则。

### 2.4 定位输入过满，作用边界不清

定位当前可注入陈述、关键词、人设、领域、受众、差异化、能力、范围、禁区、痛点、价值、语气和多条规则。问题不是定位没用，而是它可能同时参与选角度、定结构和写句子。

定位更适合做三件事：

1. 判断主题与账号是否相关；
2. 选择观众已知、关心和反对什么；
3. 守住身份、差异和内容禁区。

至于这条具体讲什么、用什么事实、怎样证明，应由本次主题、素材和已确认观点决定。

### 2.5 当前审核不是质量 optimizer

现有 `script.review` 主要判断平台合规、夸大、隐私和导流风险。它不能回答某种定位权重、结构强度或温度参数是否让文案更好。因此需要独立的实验与偏好数据，不能用“审核通过”冒充“文案优胜”。

## 3. “板块权重”应该怎样落地

不能简单写成“素材 40%、定位 20%”。大模型不会稳定执行这种数字比例。可复现的权重应拆成：

| 控制 | 含义 | 例子 |
| --- | --- | --- |
| 进入与否 | 本轮是否把该板块交给模型 | 关闭固定爆款公式 |
| 约束级别 | 参考、强约束还是不可违背 | 定位为 reference，事实素材为 hard |
| 上下文预算 | 给多少长度、几条条目 | 经验最多 3 条，素材保留全文 |
| 工作流位置 | 在哪个节点进入 | 定位只参与角度，不参与逐句成稿 |
| 否决权 | 缺失/冲突时是否阻断 | 来源事实缺失时不允许写具体数字 |

CreatorOS 需要优化的主要板块是：主题/Brief、用户素材、定位、论点、结构合同、对标方法、validated 经验、观众心智规则、固定公式、编辑修订，以及模型的 temperature/top_p/max_tokens/reasoning 等参数。

语义选择必须继续归 AI/Skill；代码只保存配置和实验事实、冻结版本、控制预算、执行顺序和确认门。不能用关键词、相似度或行业名称分支做“智能权重”。

## 4. 推荐的人工优先 loop

```mermaid
flowchart LR
  T["固定一个主题和事实素材"] --> I["当前冠军文案"]
  I --> V["只改一个板块 / 参数 / 顺序"]
  V --> C["挑战文案"]
  C --> H["用户盲选 A / B / 平局 + 原因"]
  H --> W["胜者成为新冠军"]
  W --> V
  H --> N["切换新主题"]
  N --> E["跨主题估计板块效果"]
  E --> P["提出全局权重与工作流候选"]
```

每个主题从当前生产配置生成 Round 0。后续每轮只改一个变量，例如：

- 去掉固定爆款公式；
- 定位从 hard 改为 reference；
- 定位只进角度节点，不进正文节点；
- 素材从摘要改为全文；
- 论点从 hard 改为 strong；
- 先提炼主张再成稿；
- 增加一次只针对“推进不顺”的修订；
- 固定其他条件，仅调 temperature。

用户只判断两篇文案哪篇好，并选择原因。参数差异在提交判断后才揭示，避免“知道新版本”造成偏见。单主题的胜利只更新该主题冠军；只有同一调整在多个不同主题上重复获胜，才形成产品全局候选。

## 5. 为什么人工要先跑，自动 loop 要后开

文案质量没有唯一客观答案。如果一开始就让模型自己写、自己评、自己改，最容易优化成“更符合评分 prompt”，而不是用户真的更喜欢。

OpenAI 的 GDPval 把成对人工专家偏好作为标准，LLM judge 只作粗略估计：[OpenAI Evals：GDPval Grading](https://evals.openai.com/gdpval/grading)。研究也证明 LLM 成对裁判存在位置偏差，因此 A/B 与 B/A 必须都跑，结论翻转时应回人工：[Judging the Judges](https://arxiv.org/abs/2406.07791)。

人工阶段要积累的是：

- 主题和固定输入；
- A/B 文案；
- 两套完整参数快照；
- 本轮唯一主变量；
- 用户 winner、平局与原因；
- 成本、时延和硬 Gate。

等这些数据覆盖足够多主题，再用其中一部分调 evaluator、另一部分做保留验证。Anthropic 建议把代码、模型和人工 grader 组合使用，并将生产反馈作为补充，而不是依赖单一自动分数：[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。

## 6. 自动 loop 的正确边界

自动 loop 不是“系统随便改 prompt”，而是有界实验器：

1. 从当前主题冠军开始；
2. 每轮只改一个主变量；
3. 同时交换 A/B 顺序评判；
4. 低置信、顺序冲突或新内容类型转人工；
5. 连续无提升、硬 Gate 失败、预算或轮数到限即停止；
6. 只形成候选工作流/权重方案；
7. 用户确认后才复用现有 account overlay 生效，并可回滚。

Anthropic 的 evaluator-optimizer 模式适合评价标准能被清楚表达、迭代带来可测提升的写作任务，但需要明确停止条件：[Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)。多阶段 prompt 也可以围绕下游指标联合优化，但 MIPRO 的研究说明这需要数据和模块信用分配，不能凭感觉一次性重写整套：[MIPRO](https://arxiv.org/abs/2406.11695)。

## 7. 推荐默认门槛

- 单主题人工 loop：最多 6 轮，连续两轮没有新冠军即停；
- 全局候选：同一调整至少覆盖 5 个主题、12 次有效人工比较，胜率不低于 70%；
- 自动能力可开启：至少 30 次人工判断、10 个主题、3 种内容类型；
- 自动裁判：保留判断一致率不低于 80%，A/B 顺序一致率不低于 90%；
- 自动 loop：每主题最多 4 轮；
- 生产升级：始终需要用户确认，不能由模型或线上播放数据自动完成。

这些是为了开始实验而设的默认值，可以由用户确认后写成正式 Gate；它们不是讲师方法，也不是声称已经验证过的最佳数字。

## 8. 最终推荐

下一步不要先开发声音模仿，也不要直接做全自动 prompt optimizer。先把产品做成一个可追溯的“文案实验台”：固定主题，隐藏参数，A/B 只看文案，用户连续评判；系统从多主题胜负中识别定位、素材、论点、结构、公式、经验和模型参数各自该多强、何时进入。

等人工判断足够，再启用有界自动 loop。这样最终优化的是 CreatorOS 的创作系统，而不是某个主题的一次幸运输出。
