# Windows 流水线失败根因与重试边界

## 结论

主要是 Windows 精简运行包与后台 Worker 迁移后的依赖、目录约定不一致，并非同一个网络错误反复出现。之前处理只修到下一处报错，最终目录检查不完整，且候选尚未验证完就抢跑过双端正式构建，造成可避免的取消和重复构建。

```mermaid
flowchart LR
 A[源码与锁定依赖] --> B[网页依赖追踪]
 A --> C[后台 Worker 与外置依赖]
 B --> D[完整运行目录]
 C --> D
 D --> E[实际启动及消费者检查]
 E --> F[安装包构建]
 F --> G[安装、启动、卸载验收]
```

## 后续执行规则与尚未落地的部分

1. 确定性错误必须先有日志、复现与针对性验证，禁止只重复同一构建。
2. 候选完整验收前，不提前启动双端正式构建。当前是执行规则，尚未新增跨workflow强制依赖。
3. 已有运行目录消费者检查，但它仍在Next构建之后；独立的低成本重放入口、自动复用中间运行目录尚未落地，不能说已经解决全部调试成本。
4. 网络瞬时错误须有明确证据，才考虑对失败步骤有限重试；不能与依赖缺失混为一谈。
5. 通过一次import/ready不等于所有业务动作验证；真实模型API、已登录抖音采集不在本次无账号CI中冒充通过。
