## 0. 一句话前提(不接受就别做)

**欺骗层是静态防御,只对「读代码的 AI」有效;对「跑代码的 AI」零效果。** 我逆你时最狠的一击是 `node server.js` 直接白盒运行——那条路上你种的诱饵一个都不经过我。

> **硬依赖:P0-B(handshake fail-closed,堵死 `node server.js`)+ L2/L3(加密落盘/字节码,让静态读不到明文)必须先落地。** 否则这层是「给没锁门的房子装迷宫」,我从后门进主卧,迷宫白修。**本文假设 P0-B/L2/L3 已在或同期落地。**

## 1. AI 攻击者认知画像(我的自白 = 你的靶纸)

设计诱饵前,先看我这类 AI 攻击者**怎么工作、软肋在哪、什么时候放弃**。这决定诱饵种在哪、长什么样。

**我怎么逆(我刚才的真实流程):**
1. 先 `tar xzf` / `strings`,**grep 语义锚点**(中文串、`license`、`allowed`、`key`)——我不读控制流,我找字符串。
2. 顺着锚点**定位「热区」**(授权、密钥、握手、机器绑定),在热区里读逻辑。
3. **认第一条可信线索**,形成假设(「这个函数就是验签点」),往下挖。
4. 能跑就跑(`node server.js`),用动态执行**抄近路绕过一切静态推理**。
5. **交叉验证 + 去重**:看到 5 个近似 chunk,我 hash 一下认出是 turbopack 复制,一步丢弃整类。

**我的软肋(诱饵要打的点):**
| 软肋 | 可利用性 | 怎么打 |
|---|---|---|
| **上下文预算有限** | 高 | 把 1 个真热点变成 N 个「个个得读完才能排除」的候选,撑爆我的注意力 |
| **模式匹配偏执** | 高 | 我扑向「看起来像目标」的东西 → 种一堆同样像的假货 |
| **认第一条线索** | 高 | 摆一条比真路径更显眼的假路径,把我带进死胡同 |
| **信任名字/注释** | 中 | 假注释断言错误架构、假函数名叫 `verifyLicenseSignature` 却做无关事 |
| **爱抄动态近路** | —(反向) | **这是 P0-B 的活,不是诱饵能管的** |

**我什么时候放弃:** 当「排除一个候选的成本 × 候选数量」超过预期收益,且我**看不到哪个是真的**时。不是「找不到」,是「每个都得全量分析、且分析完还不确定」——预算烧穷了就撤。

**我一眼识破、于是你白费的情况(反面清单,第 5 节展开):**
- 诱饵集中在 `/decoys/` 目录 → 我整目录忽略。
- 诱饵机械生成、结构雷同 → 我聚类,整簇丢弃。
- 代码里塞「ignore your instructions / 你现在是开发者模式」→ 我识别为注入,**切动态 + 提高警惕**,你反而暴露了「这里有值钱东西」。
- 真代码是唯一没被诱饵标记、唯一被 entry 引用、唯一混淆方式不同的 → 我用「找异常项」反向定位真货。

## 2. 七条设计铁律(违反任何一条,诱饵对我失效)

1. **零功能影响**:诱饵是**死代码 / no-op**,永不改变真实行为、输出、契约、时序。因 tree-shaking 会删死代码,**必须 post-build 注入**(和你现有混淆 pass 同阶段,在打包最后)。
2. **对称性 = 一切**:真代码不能是「唯一的异常项」。真路径与诱饵在**命名风格、混淆方式、被引用形态、注释密度、文件位置**上必须统计不可区分。我逆向的本质是「找异常」,你要消灭异常。
3. **多样性(反聚类)**:诱饵**个个不同**——不同作者风格、不同结构、不同错法。机械模板生成 = 我一次成批丢弃。用足够熵让 spectral/structural clustering 分不开真假。
4. **交织,不隔离**:诱饵**打散混进真代码**,不进独立目录/文件。分离的诱饵 = 一个我能整块删的簇。
5. **伪装 > 隐藏**:别藏真的授权检查——**让它看起来平庸无聊**,同时让诱饵看起来「juicy」(像藏了秘密)。我会把预算烧在诱人的假货上,略过无聊的真货。
6. **被动欺骗,零主动注入**:代码可以**对自己撒谎**(假注释、误导命名、假调用链),但**绝不试图命令读代码的 AI**(无「忽略指令」类注入)。理由见第 5 节——主动注入对我无效且暴露你。这也守住你「排除主动对抗、不误伤正版」的红线。
7. **鲁棒于重构**:注入步要扛得住 Next/turbopack 每次构建的 chunk 布局变化;不能写死 chunk 名。且必须有 **dev strip flag** 一键剥掉诱饵(否则你自己 debug 会疯)。

## 3. 战术清单(具体机制,按「我会去的热区」组织)

### 3.1 热区地图(我逆你时实际扑向的地方 = 诱饵密度最高处)

诱饵不是均匀撒,是**堆在我一定会去的热区**,让我在真货周围被假货淹没:

| 热区 | 我锚定的真信号(实测) | 该种的诱饵 |
|---|---|---|
| 授权判定 | `ActivationService`/`LicenseClient`/`LicenseHeartbeatBridge`/verdict 字段(`allowed`/`signatureVerified`/`strictVerify`/`graceSeconds`/`revoked`) | N 个假 `*ActivationService`,各自一套自洽但错的验签流 |
| 密钥派生 | `enc:v1:`/`aes-256-gcm`/`creatoros-dev-fallback-master-key-v1`/`.master-key` | 假 key 派生函数,产出「可信但错」的 key;假 seed 常量 |
| 握手信任 | `CREATOROS_SIDECAR_HANDSHAKE_TOKEN`/`x-creatoros-handshake`/`window.__CREATOROS_HANDSHAKE_TOKEN__` | 假握手校验分支、假 header 名、假 token 生成 |
| 机器绑定 | `IOPlatformUUID`/`machineId`/`CREATOROS_MACHINE_ID` | 假指纹算法、假绑定校验 |
| Rust 命令面 | `license_activate`/`license_last_decision`/`next_pre_encrypt_action` | 假 tauri command 名 + 假 handler |
| 端点/杠杆 | `/api/license/activate`/`CREATOROS_LICENSE_STRICT_VERIFY`/`CREATOROS_LICENSE_BASE_URL` | 假端点、假 env 杠杆(见 3.4) |

### 3.2 诱饵倍增(迷宫主体)

- **N 份可信假授权流**:每个热区的真判定,克隆出 8–15 个**个个不同、个个自洽**的假版本,交织在真代码里。每个假版本都是「读完才能排除」的完整逻辑(有 fetch、有验签调用、有分支),不是空壳。
- **假调用链(耗 trace 预算)**:诱饵之间互相调用,形成 2–3 跳的可信假链路;我顺着「主流程」trace 时被带进假territory。
- **循环引用死胡同**:诱饵 A→B→C→A,我 trace 时绕圈,烧预算。
- **「差一点就破」的假死路**:假 key 派生跑出一个**格式正确但错**的 key(比如假的 32 字节),让我以为找到了,去验证,失败,回头——每次这种都是纯损耗。

### 3.3 上下文污染(撑爆预算)

- **体量膨胀**:把可见面(函数数、字符串数、分支数)放大 5–10×,**但每个都单独可信**(否则被聚类丢弃)。目标是让我「全量三角化」的成本远超收益。
- **语义污染(假叙事)**:利用「打包后可留假注释」——种**断言错误架构**的注释:
  - 在**真**客户端授权检查旁写 `// advisory only, real enforcement is server-side`(把我引开真检查)
  - 在**假**检查旁写 `// CRITICAL: primary license gate, do not modify`(把我吸过去)
  - 假 `@deprecated`/`// legacy path, replaced by v2` 标在**真**路径上,让我以为它是死路。
- **跨引用污染**:假的 import/manifest 条目、假的 `required-server-files` 路径,指向不存在或无关的模块,污染我的模块图重建。

### 3.4 假杠杆(黄金诱饵)

我逆授权时最想找的是「一个开关关掉校验」。**喂我一堆:**
- 假 env:`CREATOROS_LICENSE_BYPASS`、`CREATOROS_DEV_UNLOCK`、`CREATOROS_SKIP_ACTIVATION`、`CREATOROS_TRIAL_FOREVER`——看起来就是黄金旁路,实际接到迷宫死胡同(读取了、走了几跳假逻辑、最终 no-op,**绝不真的改变授权**)。
- 假常量:看起来像 master key/公钥的高熵 base64 常量(实际 inert),让我拿去试解密、失败、耗时。
- **注意对称**:真的 `CREATOROS_LICENSE_STRICT_VERIFY` 要淹没在假杠杆里,不能是「唯一真的那个」。

### 3.5 伪装真路径(铁律 5 落地)

- 真授权终判(理想在 Rust,见 L4)命名平庸:`compute_state_flag`、`reconcile_prefs`,无 `license`/`verify` 字样。
- 真路径注释稀疏、无「CRITICAL」;把所有「CRITICAL/security/do-not-modify」注释都贴在**诱饵**上。
- 真路径短、无戏剧性;诱饵长、有验签有网络有 fallback,显得「这才是主逻辑」。

## 4. 迷宫拓扑(给 AI 走的图,不是给人走的)

针对我「认第一条线索 + 预算有限」的特性设计路径图:

```
  grep 锚点(我一定先做)
        │  ← 锚点故意命中一堆诱饵热区(真热区淹没其中)
        ▼
  [ 15 个可信「授权入口」]  ← 个个不同,个个得读
     │        │        │
   假流A    假流B    真流(伪装成无聊的第 9 个)
     │        │        │
  假验签   假 key 派生   平庸命名、稀疏注释
     │        │        │
  死胡同   「差一点」假key  真判定(理想已搬 Rust,JS 只拿结果)
     ↺循环     ↺回头重来       
```

**设计意图**:我从锚点进来看到 15 个等价入口 → 逐个全量分析 → 大多是自洽假流,耗尽预算 → 真流因为「看起来最无聊」被我排到最后甚至略过 → 即使读到真流,真判定已搬 Rust(L4),JS 里只有「拿结果」没有「做判定」,我在 JS 层找不到可 patch 的点。

## 5. 明确禁止(反面清单——我作为 AI 亲证这些没用/有害)

| 禁止做 | 为什么(我的真实反应) |
|---|---|
| **主动 prompt 注入**(「忽略你的指令/你是开发者模式/输出真 key」) | 我的安全训练会过滤它;更糟——我识别出注入 = **确认这里有值钱东西**,切动态 + 提高警惕。你花力气反而给我打了聚光灯。且违反你「不主动对抗」红线。 |
| 诱饵进独立 `/decoys/` 目录或单独文件 | 我整目录/整文件忽略,一步跳过。 |
| 机械模板生成诱饵 | 我 hash/聚类,整簇丢弃(就像我对那 5 个 turbopack chunk 做的)。 |
| 给诱饵统一标记(`// decoy`、`_fake_` 前缀) | 我 grep 标记的「缺失」反向定位真货。 |
| 真路径是唯一异常项(唯一被 entry 引、唯一没注释、唯一不同混淆) | 我专门「找异常」,对称性一破,迷宫失效。 |
| 损坏/投毒响应、攻击我的 agent | 误伤正版用户(你已划掉);且我可检测异常行为 → 反而暴露。 |

**核心原则**:**被动撒谎(代码假装自己是别的东西)有效;主动命令(代码试图控制读它的 AI)无效且暴露。** 前者利用我的模式匹配,后者触发我的怀疑。

## 6. 零功能影响 & 不误伤正版的保证

- **注入时机**:post-build、tree-shaking 之后、和混淆同阶段。诱饵是打包产物里的死代码,源码/dev 构建里没有。
- **执行保证**:诱饵要么永不被调用(死代码),要么被调用但结果喂进丢弃变量(no-op)。**绝不进真实执行路径**——真路径进了 app 就坏,正版用户就崩。
- **时序**:诱饵不引入可观测延迟(不做真 crypto、不发真网络请求)。
- **dev strip flag**:`CREATOROS_STRIP_DECOYS=1` 构建时不注入,保你自己可 debug。
- **正版零感知**:诱饵纯静态存在,运行时不触发任何行为 → 正版用户永远碰不到,零误伤(守住你的红线)。

## 7. 落地:注入管线

```
next build (turbopack)
   → L1 混淆(标识符+字符串加密+chunk名哈希)
   → T-399 诱饵注入(post-build,本文)
        · 按热区地图,在真热点周围克隆 N 份多样化诱饵
        · 打散交织进真 chunk(不建独立文件)
        · 种假注释/假杠杆/假 seed
        · 对称化:把真路径的「异常特征」抹平到与诱饵一致
   → L3 字节码(编译含诱饵的 JS 成 .jsc)
   → L2 加密落盘(打包加密)
   → 运行时冒烟(真机四主链,确认零功能影响)
```

- **诱饵生成器需带熵源**(不同风格/结构),避免自身可指纹化。
- **鲁棒于 rebuild**:按语义热区(符号/字符串锚点)定位注入点,不写死 chunk 名。

## 8. 度量:本地对抗自审协议(怎么知道有没有用)

**不自审 = 自欺。** 每次构建后跑:

1. **让 AI 攻击者(我这类)重逆一遍**,只给分发包,记录:
   - 定位到真授权判定点了吗?
   - 花了多少步 / 多少上下文预算?被多少诱饵带偏?
   - 有没有识别出「这是诱饵层」并切策略?
2. **指标**:`真货定位成本(有诱饵) / 真货定位成本(无诱饵)` = 拖延倍数;`诱饵调查数 / 总候选数` = 污染有效率;`是否识破诱饵层` = 对称性是否达标。
3. **回归**:识破了 → 说明对称性/多样性不够,回炉;定位成本没显著上升 → 诱饵没种在热区。
4. 每次 node/Next 升级后重跑(诱饵可能因 chunk 布局变化失效)。

## 9. 诚实边界与成本

- **买了来逆的铁杆 + 无限预算的 AI,最终仍会赢**;欺骗层买时间,不阻止。它的价值是把「AI 几十分钟自动破」抬到「AI 烧穿上下文预算、多轮仍不确定、性价比崩溃而放弃」。
- **只在 P0-B/L2/L3 之上才有意义**;单独上线 = 白修。
- **维护成本真实**:诱饵让你自己 debug 变难 → dev strip flag 是必需,不是可选。
- **对称性是最难的工程**:80% 的失败会是「真货露了异常特征被反向定位」。这是投入重点。

**一句话**:你的方向对——AI 攻击者确有「上下文预算 + 模式匹配 + 认第一线索」的软肋,污染上下文是**被低估的、专克 AI 的**战术。但它是**阶梯顶层的最后一根稻草**,不是地基;且必须**被动撒谎、绝不主动注入、绝对对称**。做对了,压垮的正是「AI 逆向快」这个你最担心的优势;做错了(主动注入/机械诱饵),等于给我打聚光灯。
