# AI 工具门禁全局审计：创作先出候选，真相与安全继续守住

> 对应任务：`T-708`
> 日期：2026-08-05
> 结论：创作完整度只能影响候选质量，不能阻止用户先得到结果；只有权限、安全、数据归属、破坏性操作、幂等冲突和不可伪造的事实，继续作为硬门。

## 1. 统一判断算法

每个工具调用前只判断两件事：

1. **现在执行会不会越权、泄露、破坏数据、重复扣费，或把假的事实写成真的？** 会就硬拦，并说清怎样解除。
2. **只是资料不够、方向没选、素材没齐、长度不确定或增强工具失败吗？** 不中断，立即产出可编辑候选，把假设、缺口、待核实项和风险显式写出来。

用户明确说“直接生成、先给一版、就按现有信息做”时，创作类工具不得再追加形式主义门槛。候选仍遵守用户采纳后才落库的确认门。

## 2. 审计结果

| 工具/场景 | 旧行为 | 新口径 | 门禁分类 |
| --- | --- | --- | --- |
| `positioning.generate` | 六问、逐字稿、联网、多个方向与选定方向可能阻断 | Copilot 三场景路由；任意时刻可先产定位候选；纯人设不强塞产品，产品型按需补产品、人群与场景 | 创作质量软提示 |
| `topic.enrich` | 时效题“先搜后卡，不可跳”，搜索失败不出卡 | 搜索是事实增强；失败仍按已确认信息出候选，时效事实标“待核实”，严禁假 URL/假来源 | 搜索软提示；事实真相硬门 |
| `script.draft` | 没聊清真实触发场景就先追问，不能整稿 | 真实资料优先；缺失时先出可编辑整稿，不编个人经历/案例/数字，标“待补真实案例” | 创作质量软提示 |
| `planning.thesis` | 立项或素材没齐先告知，不立论点 | 先出方向骨架；缺真实证据的节点标“待补证据”，不得把占位当已核实论据 | 创作质量软提示；事实真相硬门 |
| `web.read` / `local.read` 长文 | 必须翻完全文再回应，失败时容易长时间无结果 | 精确全文任务继续翻窗；快速判断或后续读取失败时先给阶段结果，明确已读范围，不把局部冒充全文 | 完整度软提示；授权与敏感文件硬门 |
| `calibration.diagnose` | 可能只有标题或只有部分稿件 | 已支持“仅标题可评”，必须明说局限，不假装读过全文 | 已合理，无需改 |
| `review.analyze` | 没有具体作品真逐字稿拒绝沉淀经验 | 保留。该工具产物会进入知识库，凭标题猜方法论会污染长期记忆 | 事实真相硬门 |
| `review.script` / `publish.package` | 当前项目没有真实整稿时不审核/不打发布包 | 保留。审核或发布物料必须对应实际稿件；但系统已有稿件时应主动读最新版本，不能因“未采纳卡”误判为空 | 数据真相硬门 |
| `cover.generate` | 无项目、生图模型未配置时失败；数字不可编造 | 保留项目归属、模型可用性与数字真相门；不能用“素材不够”阻止先产封面方案 | 归属/能力/事实硬门 |
| `local.read` 授权与敏感文件 | 首次读取需用户授权；密钥、证书等拒读 | 完整保留，不能为了“灵活”绕过路径授权或敏感文件防线 | 隐私安全硬门 |
| 所有“候选→采纳→落库” | 未采纳不写正式数据 | 完整保留；灵活生成不等于 AI 可以直接改库 | 数据完整性硬门 |

## 3. 不再允许出现的回复模式

- “六个问题还没答完，所以不能生成。”
- “你还没选 2～3 个方向，所以不能生成。”
- “联网失败，所以不能出选题卡。”
- “素材还没搜齐，所以不能立论点/写第一版稿。”
- “必须先把整篇长文读完，当前不能给任何阶段结论。”

正确做法是先给用户一版能继续编辑和采纳的结果，再用一个最有价值的问题、一次搜索或一份真实证据把下一版变准。

## 4. 仍然不能软化的边界

- 未授权读取本机文件、跨账号/跨项目读取、敏感密钥与证书读取；
- 删除、覆盖、重置、发送、发布、扣费等破坏性或外部动作的确认；
- 重复任务、版本冲突和幂等冲突；
- 把不存在的逐字稿、来源、URL、数据、案例、已完成状态说成真实；
- AI 候选未经用户采纳直接写入定位、知识库、稿面或项目正式产物。

这套边界让系统“能先做”但不会“乱做”：创作不被形式主义卡死，用户数据和事实可信度也不会被牺牲。
