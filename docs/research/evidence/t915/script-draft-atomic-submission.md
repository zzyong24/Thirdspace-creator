# T-915：整稿原子提交与生产目标类型修复

本次将正式 `dispatchScriptDraft` 的稿件目标创建与 AI 任务提交收进同一数据库事务。提交后仍沿原公开派发入口启动已存在的脚本 Worker；相同 attempt 返回同一任务。逐字导入前的聊天语义授权模型尚未迁入 Worker，本次不能记为整稿聊天工具全部迁移完成。

```mermaid
flowchart LR
  I[完整来源与稳定提交键] --> V[校验原文并冻结配置]
  V --> T[同一事务]
  T --> P[验证账号并锁定项目]
  P --> A[复用稿件或创建空白初始版本]
  A --> Q[创建原任务与真实输入指纹]
  Q --> W[提交后派发脚本 Worker]
  W --> C[原文候选]
  C --> U[用户采纳后写入稿面]
```

## 已实现

- `script-draft-task-submission.ts` 提供直接原子提交与父工具事务准备两种内部入口。配置读取留在事务外，事务内回调只读冻结数据，避免持有数据库事务时回调根数据库。
- Projects 域验证 user/account/project 并取得行锁；Artifacts 域在同一事务复用 `output_script`，否则按既有规则创建稿件与空白初始版本。未改变已有正文。
- 任务输入先确定真实 artifactId，再经原 AI service 一次生成 fingerprint、attempt 幂等和父提交绑定。未使用“建任务后补字段”的方式。
- 已有同键任务不重新 ensure；不同意图不能复用 attempt。后续删除稿件不导致回放重建已删数据。
- 原稿和资料快照校验从 frontend 移至 backend，原测试一起迁移，删除无消费者旧文件；全局保真 Gate 更新为实际新测试路径，并继续运行原候选卡测试。
- 正式 Worker 装配原先只允许 `master_script`，与正式提交始终使用 `output_script` 相冲突。生产测试重现失败后，修正为接受新目标，同时保留已绑定 `master_script` 的历史任务兼容；新提交始终只创建或复用 `output_script`。

原子提交测试覆盖：准备不写库；外层失败时稿件、初始版本与任务回滚；同键/异键并发；同键不同项目的失败方回滚；跨账号/缺账号/删除项目；原文 hash 不符；已删稿件的历史回放；不能接管其他父调用；输入与配置冻结。

生产测试使用本次创建的临时数据库目录、本机测试服务和真实 fork Worker，并拦截媒体迁移 API。没有访问真实媒体、调用商业模型、构建安装包或部署。
