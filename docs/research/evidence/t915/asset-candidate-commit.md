# T-915：生成素材候选事务

日期：2026-09-06。基线：9384f8b6。沿用已批准 SPEC 与 DEC-RUNTIME-055。

已保存的原素材现在可以经现有执行候选服务进入待采纳结果。首次提交必须证明素材和文件仍属于当前账号、仍是原产物；删除或替换过的素材不能被迟到回执重新挂回。已提交候选的重复请求只返回历史回执，不改变用户之后的操作。

## 代码与边界

- assets 模块新增专用验证端口；按原 callId 派生的稳定身份读取已提交记录，严格比对完整回执，核验 assetId、fileId、账号、用户、pending、currentFileId、类型、storageKey、MIME、checksum 与大小。
- 现有候选服务对 asset.generate 使用专用投影，通用 projectCandidate 不可绕过素材验证。冻结输入、摘要和原调用绑定由现有绑定服务验证，历史候选回放也验证这一链路。
- 执行任务、AI 任务、素材、文件按顺序加锁。验证与候选及任务状态写入共用事务；素材模块不跨模块调用 repository。
- 结果保持 generated_asset 原字段；素材仍 pending，AI 任务 awaiting_confirmation、执行 succeeded。没有代替用户采纳或修改 active 素材。
- 等待领域行锁后再次读取时间，租约或截止时间已到则拒绝候选；不会沿用等待前的时间误判成功。
