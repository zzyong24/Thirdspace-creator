# 模型配置向导代表性走查 RAT

> 日期：2026-07-24  
> 类型：PLAN 阶段纸面/交互规则走查，不冒充真实用户可用性测试  
> 目标：验证“用途优先 + Key 来源/产品线 + 模型”的向导是否只是把六个技术字段换成另一棵复杂供应商树。

## 判定门

- 覆盖 Kimi、通义千问、MiniMax、一个 OpenAI-compatible 中转站；
- 4/4 路径无需打开“原始字段高级设置”即可形成可测试配置；
- 每条路径最多 5 个用户决策，不把粘贴 Key、等待模型列表和点击测试计为产品决策；
- 普通用户不需要自行判断 `apiFormat`、拼接 endpoint 或决定是否重复 `/v1`；
- 任一路径需要在官方文档与表单之间人工翻译技术字段即判失败。

## 走查结果

| 路径 | 用户决策（依次） | 决策数 | 打开原始字段高级设置 | 主要阻塞点与处理 | 结果 |
|---|---|---:|---|---|---|
| Kimi 开放平台 | 用途=主编导 → Key 来源=Kimi 开放平台 → 模型 | 3 | 否 | 开放平台与 Kimi Code 必须是两个独立来源；选中后锁定 OpenAI Chat 与官方 Base URL | PASS |
| 通义千问 | 用途=主编导 → Key 来源=通义千问 → 产品/区域 → 模型 | 4 | 否 | 套餐/区域会改变 Key、地址和模型范围；用产品卡片解释，不暴露协议字段 | PASS |
| MiniMax | 用途=主编导 → Key 来源=MiniMax 开放平台 → 模型 | 3 | 否 | 同一厂商还有图片/视频能力，但能力由第一步过滤，文本向导不混入生图参数 | PASS |
| OpenAI-compatible 中转站 | 用途=主编导 → 来源=中转站 → 兼容协议 → 模型 | 4 | 否 | Base URL 和 Key 是该来源的必填资料，不算“原始字段高级设置”；APP 展示最终 endpoint，并将 `/v1` 作为可确认建议 | PASS |

汇总：4/4 通过；最高 4 个产品决策；0/4 需要打开原始字段高级设置。

## 走查产生的规格修正

1. “中转站专用向导”属于普通模式可见路径；只有手改 provider/raw headers/auth style 等才叫高级设置。
2. Kimi 开放平台与 Kimi Code 不可作为一个来源下的协议切换项。
3. 通义的产品/区域选择必须在粘 Key 前完成，教程和 Key 获取入口随选择变化。
4. 能力是第一层过滤器；MiniMax 文本、图片、视频不能共用一张万能配置表单。
5. 这次只验证信息结构不会必然迫使用户理解协议，不代表 UI 已经可用。DESIGN 阶段仍需在
   1280×720 APP 内做键盘、错误态和返回教程后的状态保持验收。
