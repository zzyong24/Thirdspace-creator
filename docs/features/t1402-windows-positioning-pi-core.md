# T-1402 修复 Windows 定位对话缺少 Pi 核心依赖

## 用户授权

2026-10-25 用户要求对照合作仓库与本机 Windows 安装版，修复无法账号定位的问题；本机修复验收后，用户进一步明确要求“推送并合并进 main”。此前不推送的本轮限制由该新授权更新。用户已允许跳过当前缺失的 product-to-code-orchestrator 技能。

## 故障与范围

实际安装为原版 CreatorOS 1.2.0。定位对话反复显示自动恢复无进展；后台任务失败为 WORKER_EXECUTION_INTERRUPTED，模型调用记录为空。安装版已包含既有失败重试和 DeepSeek 协议修复，不能把故障归因于这些源码尚未更新。

对随包 execution-worker.cjs 进行隔离 IPC 复现，阻断真实网络和子进程创建，使用合成凭据与端口，在 readCheckpoint 后稳定得到 CHAT_PI_CORE_UNAVAILABLE。旧加载器只搜索 cwd/node_modules 和 pnpm 完整名称路径；Windows 分层闭包缺少该可加载入口，Windows pnpm 截断目录名也不匹配旧扫描。

## 实现

- 将 @earendil-works/pi-agent-core 0.80.7 声明为 Worker 的直接依赖，复用锁文件已有依赖快照。
- 静态导入真实 Pi Agent，使其随 Worker 一起打包，移除用户机器上的路径扫描。
- 维持原工具、提示词、业务候选、账本和权限协议，不引入 coding-agent 宿主工具或用户 Skill 扫描。
- 新增回归把实际 esbuild 产物移入中文空目录，清空 NODE_PATH，在无 node_modules 条件下完成两次合成模型回执与一次真实 Pi 工具执行。
