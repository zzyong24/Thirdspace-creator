# T-971 战报视觉与清晰复盘

用户要求先文生图效果，再实现 UI。沿用 CreatorOS 白底紫色，做适合朋友圈的成绩战报。

- 删除单天/周/月/自定义分段按钮，仅保留日期范围组件和昨天/近7天/近30天快捷项。
- 导出 CSV 按钮改为导出数据，实际格式保持 CSV 与原生保存行为。
- 分享战报以账号名、一句话定位、周期成绩为主，右上放个人主页二维码；购买入口保留在底部且明确区分。
- 全部周期内作品用播放量柱状图和带来关注折线组合呈现，双轴分别标单位；不只展示前三条。作品过多时完整分组，导出不得静默截断。
- 复盘用短句说明观察、解释与下一步；不出现内部 ID、Position、A/B 线等内部术语，不重复摘要与展开内容，不把相关性断言为因果。
- 视觉稿数据明确为排版示意；实际 UI 读取真实数据，缺失不能冒充零，不将作品带来关注叫净增粉丝。

验收：先交付生成视觉稿，随后按该稿实现并验证日期筛选、全作品图表、主题适配、原生导出与分享图片。

## 已确认实现

2026-09-13 用户认可视觉稿并要求开始落地。品牌标语使用中性文字“CreatorOS · AI 创作工作台”，不使用生成图中的自创 slogan。

分享预览和 PNG 共用 Canvas 绘制；每组12条，每张最多24条，超过24条提供翻页并一次导出包含全部PNG的ZIP。所有页采用统一双轴刻度。主页二维码只来自绑定账号的真实公开地址，一句话介绍只读取已有 oneLiner；缺失时省略，不暴露完整定位档案。两个字段为可选字段，兼容既有报告缓存。

验证记录：前端日报9个测试文件40项通过，含49条作品完整导出3张PNG的ZIP；后端身份字段、归属与旧缓存兼容测试13项通过；前端TypeScript通过。通过真实公共CLI读取8月14日至9月12日的12条作品，在浏览器运行产品同一Canvas渲染器验图，12条全部呈现。视觉稿位于 `docs/design/t971/report-concept.png`。原生CSV保存沿用现有实现，Windows真实保存面板本轮未实机验证。
