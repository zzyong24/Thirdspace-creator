# T-1207 全功能逐项验收与截图留证

## 用户目标

按用户给出的验收方式：先把范围与验收标准写清楚，让AI写用例与流程，由子Agent实际用Playwright在浏览器中跑E2E、保存屏幕结果；桌面App用可用的原生App自动化能力逐项跑并留图。用户次日查看截图把关。

## 范围与实际验收

- 浏览器使用现有隔离 Playwright 配置，全新临时 PGlite 和临时登录态；外网请求由测试策略拒绝，不碰安装版生产数据。
- 盘点完整现有 `frontend/tests/e2e/*.spec.ts`、认可页面路由、视觉/无障碍套件和可操作功能，建立页面/流程→用例→截图→真实状态矩阵；逐步运行全部现存46个E2E文件，保留每例原断言和真实失败，禁止删除/跳过来造全绿。
- 为成功与失败的每条实际浏览器场景生成一次截图和记录：spec/title、URL、viewport、结果、文件名、关联Playwright trace/error；至少另生成全路由屏幕索引。避免截图携带真实账号资料。
- 在仓库本机只读确认 macOS app automation runtime、Appium mac2/同级能力是否可实际启动；当前未确认 Appium 已安装。可用时对安装版及其真实 UI 走主用户流程并留截图；不可用时明确具体设备/driver/权限障碍，完成浏览器所有独立可跑项目，不伪称桌面App通过。
- 自动化登录/绑定扫码、连接第三方平台、真实采集与发布、调用付费模型或远端生成，不做实际业务写入；只验证被本地/第三方测试服务明确允许的模拟边界。真实集成缺少凭据或外部环境时如实标记无法验收，不使用用户账号填充测试库。

## 证据要求

证据位于 `docs/verification/t1207/`：机器可读每例结果与截图索引、失败截图/trace、全部 E2E 汇总、独立应用自动化探测结果和人工验收入口。报告既列覆盖也列未覆盖和每个真实失败；Playwright E2E、页面视觉/无障碍基线、已安装App原生交互互相不可替代。截图文件本身必须来自真实浏览器/App当前运行状态，不能用已有设计稿代替。

## 完成条件

至少一次完整 Playwright E2E 命令完成且有实际总数和明细；每个成功/失败浏览器用例都有截图或有准确失败原因；页面和核心业务旅程逐项映射；每个功能覆盖缺口、运行失败、三方实测限制明示；桌面原生App逐项运行及截图只有在真实Appium等宿主工具可用时签通过，否则以实测能力探针记录阻塞并保留该部分未验，不冒充全部功能完成。机器报告、截图索引及失败可直接查看，用户可据此人工把关。
