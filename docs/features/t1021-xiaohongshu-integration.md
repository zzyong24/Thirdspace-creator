## 迁入范围与适配

审查并迁入本地工程的登录/身份核验、独立浏览器档案、`worker/src/collector.ts` 正常页面响应读取、`analytics-parser.ts` 字段字典、全量目录分页和 `session-pool.ts` 互斥租约。保留可追溯的来源 commit 与差异，按 CreatorOS 的 Worker/后端端口和账号 `RequestContext` 重组。Cookie 留当前账号本机档案；平台返回数据先校验真实身份、页面来源、schema、时间范围及完整性，再映射 T-1020 快照。当前 `parsePosted` 未保留平台可见性/审核状态，实施需从正常页面目录/详情或可靠的可见性来源补采并存 `visibilitySource/ObservedAt`，不能把“在笔记管理出现”推断为公开。全量重扫或状态回读发现转私密/隐藏/删除时生成云端删除墓碑，状态未知时停止该作品出站。未知/失效/限流/页面变更给稳定错误码和可操作提示，不用猜测数据补 0。本地[实查报告](/Users/zyongzhu/Workbase/Thirdspace-xhs-creator/docs/research/xhs-creator-discovery.md)曾在粉丝页看到总数，并观察 `/api/galaxy/creator/data/fans/overall_new` 的正常页面响应；它未将总量字段纳入当前解析器。实施需重新核实总量所在的确切字段、权限、时间口径和两个账号结果，不能由观察到页面数字直接推断接口稳定。

## 用户流程

账号页选择小红书，打开官方创作者页面扫码并确认平台身份；可重复绑定但同一平台身份不能悄悄覆盖另一个 CreatorOS 账号。完成后按账号独立同步账号概况、全量笔记目录、各笔记可得数据，并单独验证粉丝**总量**可用来源；原工程的 `followers` 字段是区间 `net_rise_fans_count`，不能当总量。目录不是 7/30 日概览的子集。分页未完成时保留旧完整目录并显示本次已读取数与总数，不把部分结果冒充全量。采集可手动触发、按既有调度错峰运行、取消与恢复；用户知道上次采集时间及哪些指标不可得。

## 验收

两只用户授权的小红书账号真机扫码并重启，验证独立档案、身份错号拒收、全量分页与官网可核对、每笔记指标和粉丝总量的**独立来源**；若总量来源无法验证，此项不记通过并呈现缺口，不用区间净增顶替。其中一号过期或限流，另一号继续采集。旧值/缺值/真 0 和页面字段变化可区分。与 T-1017 上报解耦：本机采集即使未授权云端共享也正常，授权后仅白名单投影出站。Mac/Windows 打包后的浏览器资源、进程恢复与账号隔离需当场证据。
