# T-1059 — 锁定已有 Codex、WorkBuddy 接入代码与复用路径

## 用户约束（2026-10-04）
用户明确：不考虑 CodeBuddy；优先寻找已经接入 Codex 或 WorkBuddy 的开源项目，复用代码实现，严格禁止从零造轮子。该约束覆盖后续接入实施。沿用 T1058 已确认的统一合法激活、渠道/自配/Agent 按能力组合、ACP/MCP 两方向、底层工具由产品接入。

## 本轮范围
在 T1058 调研基础上锁定已存在的可复用实现。公开源码只读核对固定提交、许可证、实际调用链与依赖；结合本项目已有 MCP、任务工具及 Worker 服务，交付具体到文件/函数的复用清单和实施边界。当前仍是来源与复用路径核实，不将未完成的产品接通宣称为实现成功。

1. Codex 优先核对维护中的 codex-acp，以及已经在桌面产品里消费该适配器的实际代码；协议、会话和事件桥接复用已有实现。
2. WorkBuddy 查找真实已接入的开源实现，分别核对桌面 MCP、官方云端 ACP 方向；仅在 README 写支持、实际启动另一个产品或没有明确许可的仓库不能当作可用代码来源。
3. 复用本项目已有 contract→dispatch、MCP、execution_tasks、backend service ports、候选采用和 CAS；仅允许将既有实现接到这些服务的必要适配，不另写协议栈、会话系统、模型执行器或底层下载/转写/渲染工具。
4. 开源代码许可、宿主依赖、工具授权范围、图片回执、取消/恢复和真实版本能力缺口如实列出；不运行第三方脚本、不安装软件、不读原始凭据、不做浏览器自动化或真实 Agent/模型探针。

## 交付与检查
交付复用矩阵：来源/固定提交/许可/已接入证据/具体代码/可复用部分/本地接点/明确不复制部分；一张通俗数据流图；CodeBuddy 排除决定。独立复核事实和边界。使用既有流程检查与静态差异检查，保留全局既有对账欠债，不能伪造真实连接、测试或 UI 旅程。

没有找到可合法复用的 WorkBuddy ACP 实现时，明确该方向的来源缺口，采用已有 MCP 接入的可复用代码作为可证实路径；不以自行新写 WorkBuddy bridge 满足清单。运行时改动须依经过评审的具体源码复用合同，不额外索取用户已确认的产品方向授权。
