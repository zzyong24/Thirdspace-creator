## 产品行为与边界

- 以真实本地账号组为定位所有者，允许平台账号数量为零。不要求抖音登录、Cookie、作品同步或公开网页访问；不新增假账号或放宽用户、账号组和任务的归属校验。
- 默认入口为创建或选择账号组后开始定位。首页引导和建组成功态不再把平台绑定列为必做步骤；平台连接及历史资料同步保留为可选入口。查看其他账号组时，先通过既有切换检查再进入其定位。
- 定位依据本人自述、已有定位及可用本地资料。附件为可选补充；未知信息留空或待验证，不编造粉丝、播放量或经营实绩，不要求先完成问卷或扫码。
- 普通开场只生成候选，用户明确采纳后才写入当前账号组定位母版及版本。免登录不会自动切换为从零开始，也不会忽略或清空旧定位；既有明确选择“继续深入当前账号”的 optimize 授权语义保持不变。
- 原子采纳与 legacy 适配均保留五项稳定定位字段：`contentScope`、`avoid`、`corePain`、`coreValue`、`tone`。AI 候选空白视为未知，保留旧值；手动编辑的显式清空合同不变。已停用 `statusNote` 不作为候选定位字段采纳。
- 采纳后通过现有项目入口创建项目；后续功能继续读取同一账号组定位上下文，不新增平行定位系统。项目创建成功不等于选题、校准、知识蒸馏和复盘全部通过真实模型复验。

## 相关恢复与诊断修复

- 自动重连只观察原任务；恢复请求必须携带原对话、用户消息和执行任务的完整回执，并通过后端归属核验。明确恢复沿既有持久任务许可执行，未知工具不得重放，缺少回执不得降级为新提交。
- 新对话、选择历史及取消使旧观察和迟到回调失效。模型未返回完整结果时保留输入与已完成内容，明确显示暂停状态，不伪装成功或自动重复生成。
- 首次定位进入模型设置再返回时，使用一次性内存快照保留未发送文本和附件。快照绑定工作区、路由、会话及轮次；换组、新对话、历史切换或入口变化不得串入旧草稿，不自动发送，不把草稿或文件写入 URL、日志或持久存储。
- 模型断流诊断仅记录白名单状态分类、是否已有输出及原任务编号，不记录原始上游文本、模型凭据或调用内容，不改变模型执行与重试结局。
- T-1407 中尚未验收的 Windows 扫码文件保存补丁已排除。本任务不宣称修复抖音扫码登录，不包含 PR #11 的其他修复或历史构建制品。

## 验收要求

1. 无平台账号的真实账号组可打开定位、编辑自述并生成候选；无工作区仍要求先创建或选择账号组。默认不自动采纳，原定位不因免登录被清空。
2. 用真实本地数据库与受控 HTTP 模型检验生成、候选、显式采纳、母版和下游上下文回读；覆盖跨组拒绝、重复采纳幂等、未知字段保留与手动清空。受控模型结果不得写成真实供应商验收。
3. 用真实聊天 SDK 及服务边界检验原任务观察不重复提交、明确恢复许可、未知工具拒绝、取消和历史切换隔离；验证模型设置往返的文本与附件保留。
4. 在 main 候选上重建 worker，并完成相关测试、类型检查、frontend 生产构建、boundary 和 timeout-policy。旧基线的通过结果不得替代候选检查；失败及未执行项保留真实状态。
5. 对具备授权与模型配置的独立测试工作区，复验零平台账号下的真实模型候选、手动采纳、刷新回读及项目创建。凭据不可用时列为受阻，不读取或复制原业务库及密钥。
6. 合并以候选实际 CI 与仓库要求为准。正式 UI 过程门、完整 reconcile、签名安装包及原 Windows 安装的验证单独记录，不以源码或开发实例通过代替。
