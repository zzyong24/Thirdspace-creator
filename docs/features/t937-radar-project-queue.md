# T-937 内容雷达作品升级项目

用户 2026-09-08 明确要求：将手动转写改成 AI 转写；转写状态无需切 Tab 自动更新；每个作品提供一键升级为项目，支持连续添加任意多项，后台排队依次转写逐字稿、拆解选题、生成文案；修复 WORKER_EXECUTION_INTERRUPTED。

## 使用方式与归属

点击作品上的“升级为项目”即授权该作品进入处理队列及创建关联项目，不代表发布或覆盖已有人工稿。生成文案保留候选版本。重复点击和重启必须复用同一在途队列项和已创建项目。已有逐字稿应复用；缺失时自动 AI 转写。单项受阻不阻塞后续作品，取消停止后续步骤但保留已完成产物。状态来源是服务端，前端只刷新显示，不承担后台编排。

## 实现边界与验收

复用现有 intelligence/service、task/execution、project 服务端口和 Pi 执行权；不引入第二数据库、浏览器内队列或 AI 直接写库。先查现有项目候选流水线再确定契约增量。运行中断须区分用户取消、进程中断、可重试错误和未知副作用，不把所有异常无差别重放。通过针对性队列幂等/恢复、前端自动刷新与账号隔离检查；实际安装验证据实记录。全局旧工程对账沿此前用户暂缓授权，不宣称全绿。

独立评审 radar_review 已核对现有端口：topic_preview 已包含拆解、选题、初稿；旧 confirmTopic/promote 创建链存在非原子窗口，不适合直接自动重放。采用 projects 窄服务端口原子 ensureRadarProject，以持久 queueTaskId 派生稳定项目 ID，保留完整阶段和来源/初稿 seed；不额外执行第二次写稿。父队列使用专用 radar_project_upgrade kind 和短 tick，等待子任务让出执行槽；原任务和候选可持续恢复。新增 enqueueIntelligenceProjectUpgrades / intelligence.projects.enqueue，读状态复用 execution.tasks.list。进入 BUILD，用户本轮确认构成新增按钮、自动队列和创建项目范围的授权。
