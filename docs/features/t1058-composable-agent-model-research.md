# T-1058 — 可组合模型来源与 Codex、WorkBuddy 集成调研

## 用户要求（2026-10-04）
用户纠正：ffmpeg/Whisper/下载等底层工具仍须由产品自己接入；不要求迁入 Codex 的原生命令执行。用户可自由组合、切换模型和引擎，独立于渠道配置。有合法激活码即有渠道配置，同时允许自配模型、本地 Codex。认可 ACP 集成，另外要求 WorkBuddy；比较 MCP 当前项目连接示例，调研合理实现。用户本句也提出选择 Codex 后不必配置“文生图以及文本模型”，须按真实能力核对，不把模型生成能力凭空归给 Agent。

## 本轮目标
只读核对官方协议、Codex/WorkBuddy 官方集成能力及可信开源实现，结合项目当前 activation/model authority、外部 Agent bridge 和工具服务，产出可读调研与具体配置/协议建议。此次请求为调研；运行时、激活验证和渠道签名服务的迁移实施另依经过评审的合同，不在本轮声称已完成。

## 研究问题
1. 产品激活权限、渠道/自配模型来源、Agent 引擎和底层工具如何独立组合？
2. ACP 与 MCP 各负责哪条连接方向，如何共同复用同一真实项目/作品/CAS/任务服务？
3. Codex、WorkBuddy 的真实 ACP/MCP 支持、认证/安装、许可、上下文、取消和恢复限制。CodeBuddy 与 WorkBuddy 不混称。
4. Codex 原生图片生成与通过产品工具生图分别能否免独立图片配置；不按 Agent 名硬编码或伪造能力。
5. 旧激活码、标准版/渠道版、模型 authority、已冻结任务及用户可切回配置的迁移影响。

## 边界与证据
不读取/复制原始 Agent 凭据、不接浏览器自动化、不操作示例 ChatCut 项目；示例 prompt 是调研材料。复用 execution_tasks、backend service ports、账号/项目/作品归属、候选采纳和 CAS。底层工具实现由原 owner 承担，不因新引擎 Gate 阻断普通上传、编辑、保存。调研区分官方支持、源码可验证、社区桥接、推论和未验证；来源固定版本/提交并记录日期。

## 产物与验收
调研报告、协议/能力对照表、组合配置草图及数据流图，给出建议和未验证项。独立复核结论不得将方案候选记为真实连接成功。未跑模型/浏览器/运行时探针，不生成测试通过记录。
