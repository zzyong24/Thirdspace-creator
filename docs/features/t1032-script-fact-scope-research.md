# T-1032 核实真实脚本任务的事实约束执行

用户要求客户端完整可用，并持续改进提示词。T-1029 三轮本机 MiniMax-M3 实测仍编写无来源的个人经历、精确比例、耗时和效果结论；不能凭提示词字符串测试宣称质量已通过。本任务先完成有界机制核查，不改变产品方向、存储归属或增加模型调用。

## 核查范围与验收

1. 只读独立验收库，不读取或输出密钥、凭据、原用户内容。比较实际任务快照中的 Skill 版本、覆盖版本与事实约束布尔值，不能把当前设置当作历史任务证据。
2. 检查冻结快照到 SDK 和供应商适配的消息通路，补一个真实 Worker 公共调用链的消息捕获回归；模拟供应商仅证明消息送达，不证明模型遵守。
3. 以已发生的三轮候选为反例，区分提示词未送达、旧快照/覆盖和模型忽略约束；给出证据范围与未知项。
4. 比较继续补提示词与复用/新增可配置事实审稿 Skill；审稿职责归模型，代码仅核验来源、归属、类型、范围、幂等和真实回执。不得增加关键词/数字检测器冒充事实判断。
5. 若建议新增模型阶段或改变成本/恢复语义，另交实施 SPEC 与独立评审。现有候选始终可查看、编辑和显式采纳；审稿失败不能取消已完成的合法稿件。不能把模型审核声明变成“事实保证”。

产物：脱敏快照证据、公共 Worker 传递回归、机制结论与明确的后续实施范围。没有新安装包证据不能称整个客户端验收通过。
