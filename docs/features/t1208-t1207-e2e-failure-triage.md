# T-1208：复核 T-1207 暴露的浏览器功能失败并修复确认缺陷

## 背景与事实

T-1207 在隔离 PGlite 和本地服务中运行现有浏览器 E2E：120 cases / 47 specs，73 passed、39 failed、8 timed out。每例有 URL、状态和截图。专项复跑已修正 T1069 的丢失临时媒体样本后 1/1 通过、T954 复盘 1/1 通过、T1159 微信空报告/身份拒绝 1/1 通过。仍有项目创建、定位中心、内容雷达、账号与作品页、发布日历、剪辑决策回读、画布等真实流程失败待逐项定因。旧页面结构/交互断言漂移已在 T-1207 报告中单独分类，不能预设为产品缺陷。

## 目标

从 [T-1207 逐例索引](../verification/t1207/E2E-CASE-INDEX.md)、[测试报告](../verification/t1207/T-1207-SUITE-REPORT.md) 和截图图库出发，逐个复核仍失败的可操作功能旅程。每条结果必须明确属于真实产品缺陷、测试夹具/契约漂移、环境/服务故障或不能复现；对确认的产品缺陷完成有范围的修复和验证。

## 执行边界

- 使用当前 main、隔离测试数据和公开服务入口；不触碰安装版用户数据、真实平台账号、扫码登录、外网采集发布或付费模型。
- 先以截图、实际页面状态、服务请求与持久化回读复现，不根据单个旧断言推断产品故障。
- 既有任务已覆盖的根因（例如 T-1201、T-1202）不得重复实现；有架构、服务契约、数据归属或产品流程变化时，先建立专项 SPEC 并完成独立评审，再改动。
- 保留 T-1207 全量基线与失败截图。不得删测、跳过、缩短合法流程、放宽超时或批量更新视觉基线来造全绿。

## 验收标准

- 为 T-1207 的每个仍失败的可操作功能用例给出证据化分类和根因；实际确认的缺陷修复后，关联公共链路可重复通过。
- 仅当现行产品合同有独立证据支持时校准过期测试；保留修订前失败证据和变更理由。
- 视觉基线差异独立确认是产品变化还是旧基线漂移，不把截图可渲染等同于像素验收通过。
- 新增或修复的测试继续使用真实隔离 ID、请求和回读；截图与失败 trace 不覆盖原始验收记录。
