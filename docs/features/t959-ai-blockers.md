# T-959 阻断性 AI 问题修复

用户已明确要求优先优化阻断问题。真实证据见 docs/verification/t957-full-ai-20260912.md。

范围：写稿无sourceRefs时保留instruction，项目原稿由宿主真实reader提供受信来源而非让模型猜ID；诊断绑定项目时宿主加载当前真实稿，不能因模型遗漏script而按无稿评分；审核的字面词表命中仅作语义复核线索，不能单凭命中阻断，保留真实语义风险判定与明确用户规则。禁止增加QQ/游戏等语义白名单。禁止自动采纳、覆盖稿件或发布。暂不扩大到Gemini协议、网页检索、泛化文案质量和视频颜色。

边界：沿现有backend service与worker执行链，不新建状态服务、不改数据归属。工具变更须冻结新定义版本；旧未知调用不重放。模型判断语义，代码只校验引用/版本和协议。

验收：修改前真实失败证据+红测；无来源写稿指令传递/多源引用/原文保真回归；诊断有稿/无稿/归属隔离/真实host调用链回归；审核词命中与语义判定分离、真实导流仍被模型识别、模型异常不伪造安全结论。相关类型检查和边界检查；保留既有全局失败。真实复测候选，不应用到用户稿。

流程图：用户要求 → 宿主读取原稿并保存指令 → 模型生成或语义审核 → 可审看结果；字面词命中 → 语义复核，而非直接阻断。

实现约束补充：完整用户要求与模型建议分别标注优先级，不截断末尾约束。宿主内部指令上限 210000 字符；外部模型 instruction 仍为 4000。保留最多 16 份显式资料的顺序，再追加宿主当前稿；内部最多 17 份、400000 字符，正文 hash/归属/版本校验保留。旧直接 dispatch 分支共用指令冻结函数，任务入队和 Worker 准备均保留无来源指令。

独立评审：t959_design_review 对方案 PASS；首次代码复审指出长要求截断和附件排除当前稿，两项修复后复审 PASS。真实模型验收仍需单独记录，不以模拟模型测试替代。
