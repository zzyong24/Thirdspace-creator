# 3940 筛选区修复后复测：独立复核

本记录只复核 3940 的原始报告附件、页面截图、E2E 顺序与运行收据。它与本目录的 `REPORT.md` 分开保存，不改写或覆盖原结果；也不把同一测试的部分通过记为整条通过。

## 实际结果

Playwright 单次运行自然退出码为 1，耗时 35.837 秒，1 worker、0 retry；3663 项冻结清单、HEAD 与被测源前后相同，无服务残留，外部网络尝试为 0。实际产品源 SHA-256 为 `21b0f1e361a569347349855dc71faece9fda6656ec90ee480627b05cc3cb8414`，测试源为 `748976450dc39d1f59991c79a624775cd993ffc6cd5e57b36c27cb635cf0e1a7`。

原 390px 横向溢出检查、账号组筛选区、快速创建卡片、原作业行及运行详情检查均已走过；900px 下筛选、卡片及原作业行检查也已走过。错误发生在 900px 运行详情弹层标题与关闭按钮的相对位置断言（测试第 214 行）：测试取得标题文字各行的实际矩形，要求每行与关闭按钮分离；至少一行没有满足此条件。实际失败截图显示运行详情标题携带较长作业名和 ID，文字延伸到右上角关闭符号旁，支持这项失败是可见的标题栏拥挤，而不是接口调用失败。原错误上下文中的真实报错为 `Expected: true / Received: false`，定位在标题与关闭按钮分隔断言。

我实际查看了 [3940 原始失败截图](./original-common-failure.png)、900px筛选图和900px快速创建图。900px筛选图里两个筛选器已在卡片内横向排布，账号卡片文本也没有撑出边界；390px筛选/卡片图同样在证据清单中。错误发生前，测试已完成 390px 的整轮几何与内容检查，并在 900px 完成页面横向溢出、筛选控件、卡片标题与原作业行检查。运行随后立即在标题分隔断言失败，因此 900px 弹层的后续错误提示区域检查、1536px整轮检查以及最终公共回读/错组负例没有到达，不能按整条旅程通过。

## 对后续候选修复的判断

本轮 390px 与 900px 已到达的检查说明 3939 中筛选区的横向溢出在当前 21b0 源上未再触发，且两档视口的筛选/卡片/作业行视觉检查都已实际留图。这能支持“筛选区 patch 在已覆盖部分表现正常”，不能证明整条自动化旅程或所有视口已通过。

当前选择的 [dialog-header-selected.patch](../dialog-header-selected.patch) 只改运行详情标题栏：让标题容器可收缩、允许长标题断行，给关闭按钮预留右侧空间，并固定时钟图标宽度。改动点与 3940 实际失败的标题/关闭按钮几何直接对应；但 patch 本身不是验证证据。3940 使用的是修复前源 `21b0…`，后续源哈希不能回填成 3940 的通过结果。标题修复效果、1536px视口和被截断的后续公共读回仍需以后续隔离运行独立核实。
