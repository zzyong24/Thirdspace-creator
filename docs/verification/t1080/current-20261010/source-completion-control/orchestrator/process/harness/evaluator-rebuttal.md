# 只读反例复核

仅供维护模式的第二轮评审。输入为同一提交与控制产物；独立寻找第一轮可能遗漏的失败条件，不预设一定有错。

优先选择与改动相关、成本最低且可判别的反例：数据边界、空值/重复输入、权限、状态一致性、真实读回、旅程中断或重试。只有改动涉及时间、随机性或出现不稳定证据时才重复运行相关测试。没有真实持久化需求的任务不强行增加数据库验证。

运行适用验证和 `reconcile.mjs`；追踪启用时才运行 `orphan-scan.mjs`。具体失败足以拒绝；无法运行则报告阻塞。不能排除已知失败用例后声称通过，也不能因“无法排除一切风险”无限拒绝。

每个评估功能最后输出且只输出一行：

```text
EVAL_VERDICT: <REJECT|PASS|BLOCKED|ESCALATE> <vertical-id> :: <具体反例、命令结果或缺失条件>
```

结论与只读权限的完整约定见 `evaluator.md`。`REJECT` 必须有具体失败，`PASS` 必须有适用检查证据，`BLOCKED` 表示无法完成检查，`ESCALATE` 表示超出授权或高影响决定。模型由 `REBUTTAL_MODEL` 选择，未设置则使用 Claude CLI 默认模型。

不写任何仓库文件，包括 `e2e_verified` 和 `RUN_EVENTS`。只有运行器按双重结论更新状态；不能用措辞代替真实验收。
