- 复核时间：2026-10-09T15:29:00Z

## 结论

现有证据足以把变化区间收窄为 **准备好的视频进入 HyperFrames 浏览器合成之后、`render_raw.mp4` 形成之前或形成过程中**。它不支持“最终 faststart remux 导致变暗”，也不支持直接修改 executor 输入归一或用固定增亮值补偿。

现有证据尚不能在以下三者中作唯一归因：

1. Chrome 对 `<video>` 的解码与色彩管理；
2. HyperFrames `beginFrame` 捕获返回的实际 PNG/RGB 像素；
3. 当前生成模板的背景、环境层、边框及视频合成共同造成的画面值。

因此当前没有足够依据选择产品修复点。T1135 应继续暂停产品改动，不能签修复或安装通过。

## 已证事实

1. 当前实际依赖是 HyperFrames `0.7.54`，CLI 文件 SHA-256 为 `1250669d...`。生产 executor 将 `videoFrameFormat` 固定为 `png`，本次日志记录 `captureMode=beginframe`、245帧完成。
2. 原源对应像素为 `17/36/57`；准备输入为 `15/35/56`，只发生小幅变化；`render_raw.mp4` 为 `3/22/43`，`final.mp4` 保持 `3/22/43`。最终步骤是 stream-copy/faststart，并未再次编码视频，所以 final 不是变化首次发生点。
3. HyperFrames 的普通 SDR 编码路径从 PNG/image2pipe 输入，软件 H.264 路径显式使用 `scale=in_range=pc:out_range=tv`，写入 BT.709/tv 标签。已有孤立 PNG 编码三变体均读回 `17/36/57`，包括当前 scale 形式；故“这些 FFmpeg 参数本身必然压暗”已被现有样本反证。
4. 当前生成 HTML 不只是裸视频：含 `#08090a` 背景、grid/glow、ambient、视频边框与阴影。虽然既有10点读回在当前纯色样本中均一致，仍不能把输出像素直接等同于 `<video>` 解码像素。
5. 现存 PNG chunk 记录仅说明所检查 PNG 没有显式 sRGB/gAMA/cHRM chunk；孤立编码仍保持数值，因此“缺 PNG 色彩 chunk”本身不足以解释本次差异。

## 采样充分性

当前采样对“差异真实存在、raw 与 final 相同”是充分的：固定时间映射为 source 7.06 秒与输出 0.3 秒，多处网格读数一致，文件与像素 SHA 已冻结。

当前采样对“确定根因”不充分：

- 样本画面近似全屏纯色，不能区分视频像素、模板背景及合成层；边缘点尤其受全屏元素边界影响。
- HyperFrames 渲染临时帧已清理，现存目录没有实际送入编码器的 `frame_*.png`。`original-extracted-png-chunks.json` 不能替代该帧身份与像素证明。
- `captureOperation=encode` 是阶段结束时的观测字段；它证明帧已完成，不证明某一捕获帧的原始像素。
- 没有同一帧在 Chrome `<video>` DOM、BeginFrame 返回字节、编码后 raw 三处的逐级身份绑定。

## 过程边界

研究卡明确晚于三组诊断建立。`gateOpenedLate=true`、既执行3组、未来新实验预算0是真实过程缺口，必须永久保留。不能把当前静态复核写成前置研究 PASS，也不能重置计数或补拍“先开门再实验”的历史。

现在允许的工作仅限：继续阅读当前 CLI/executor/template 与已存在文件、形成精确候选 SPEC。当前不允许新的渲染、变体、模型、App或数据库实验。

## 合法下一步

在当前“新增实验为0”的约束下，只能形成一个 **待独立批准的诊断/修复 SPEC 草案**，不能直接改产品。草案应把下一次必要动作明确成一个新的、显式审批的研究续期决策，而不是暗中重置原预算：

- 只针对同一冻结输入和同一生成 HTML；
- 保留一张 HyperFrames 实际捕获并送入编码器的 PNG，绑定帧号、source time、文件 SHA 与像素；
- 同帧读取 DOM `<video>` 内部可见区域，避开边框/阴影/背景层，绑定几何坐标；
- 比较捕获 PNG 与 `render_raw.mp4` 同帧；
- 只观察，不改变颜色、模板、编码参数或用户文件。

这会是新的实验，只有治理层明确记录为何原预算不足、批准一次有界续期并经独立评审后才可执行。若不批准续期，T1135 应保持暂停/未知，不能凭静态推断实施。

若上述现有或将来证据证明捕获 PNG 已是 `3/22/43`，修复范围才可继续收窄到 HyperFrames/Chrome 捕获或模板合成；若捕获 PNG 接近 `15/35/56` 而 raw 变暗，才可收窄到 HyperFrames 编码入口。两种结果对应不同写集，目前不能预选。

## 不成立的修复范围

- 不应修改最终 stream-copy/faststart。
- 不应对所有视频做固定增亮、gamma 或颜色矩阵补偿。
- 不应把未知色彩标签一律解释为某个范围。
- 不应以单点/纯色样本推广到 HDR、不同编码、不同平台或所有模板。
- 不应修改原用户素材、原任务、已采纳成片或模型行为。
