## 0. 目标(SPEC 原文)

客户端所有对外跳转(购买/续期、联系授权方、下载新版)按**激活码所属渠道**运行时下发;**包内官方链接硬编码清零**;更新改「版本检查 + 跳渠道链接(飞书/网盘)」。红线:**包内官方链接零命中、null 不回退官方链接**(防泄官方定价)。

**关键心智模型(先读,别搞复杂)**:
- **单一安装包,绝不分包**:所有渠道下的是同一个二进制;渠道身份跟着**激活码**走,链接由服务端按码运行时下发 + 客户端缓存。**不要 per-代理打不同包**。
- **渠道链接仅作用于「激活之后」**:激活前客户端不知道渠道 → 中性降级(无链接,纯文案「请联系你的授权方获取激活码」)。**别为了未激活态去按渠道显示链接而把激活页搞复杂。**
- **首次下载 + 发码不经 app**:新客户的「激活码 + 首次下载链接」由**代理在私域直接给**(代理自己的飞书);app 侧只管激活后的 买/续期/联系/更新 绑定到该渠道。两段各司其职。

## 1. 服务端归属结论(2026-07-19 核实 · 关键)

**T-396a 服务端全部落 `activation-manager`(`https://license.aitongban.cloud`),不要放别处。** 依据:

1. **激活码在它这,渠道戳打在码上**(2026-07-19 修订:projectKey=产品维度而非渠道,全体代理共用;码→代理归属在 agent-hub 台账。渠道为独立 `Channel` 实体 + `ActivationCode.channelRef`,发码时由 agent-hub 传 `agent-<account_id>`,官方直发=`official`,详见 SPEC §3 修订版)。
2. **代理分销台(agent-hub / Thirdspace-growth)调它的 API 发码**:渠道链接配置和发码放一起,一次配好跟码走。
3. **它已在发 `activate`/`status`(app 面响应)**:加 `channelConfig` 字段是最小改动。
4. **Ed25519 签名链已部署在它这**(`activation-manager dfe7cfc`),响应签名直接复用。
5. 栈 = Next.js,加列 + 端点 + 后台表单,改动轻。

**⚠️ `latest-version` 端点也放 activation-manager**,别放 `creatoros` 静态站——版本检查要「验激活码 → 查该码渠道 downloadUrl → 签名」,三件都是 activation-manager 的活。`creatoros.aitongban.cloud/updates/latest.json` 退成**内部记录**即可。

## 3. 三片任务

### 🅰 T-396a 服务端 —— activation-manager 仓(2026-07-19 §3 修订版)
- 新增 `Channel` 实体(`channelKey` 唯一 + `name` + `{purchaseUrl, supportUrl, downloadUrl}`,三键可空,只收 `https://`,服务端强校验)+ `ActivationCode.channelRef` 可空列(索引);generate 载荷新增可选 `channelRef`(agent-hub 传 `agent-<account_id>`,后台直发默认 `official`,省略=不戳向后兼容);`PATCH /api/admin/codes/channel-ref` 存量回填;`PUT/GET /api/admin/channels*` 管理 API(agent-hub 老板后台要调,growth 仓 T-020)。
- 后台表单:官方给各渠道代配这三个链接(**不做代理自助后台**,入口可控防恶意链接);编辑面主入口在 agent-hub 老板后台。
- `activate`/`status` 响应体加 `channelConfig` 字段,**随现有 Ed25519 签名**(签名串含 digest,免费获得防篡改)。
- 新端点 `POST /api/app/latest-version`(带激活码)→ `{latestVersion, releaseNotes, downloadUrl}`;**无码/无效码只回版本号,downloadUrl=null**(不泄默认渠道)。
- 全局应用版本公告(`latestVersion` + `releaseNotes`)后台可编辑;downloadUrl 按渠道取各自 `channel_config`。
- 单测。**验收**:activation-manager 测绿。

### 🅱 T-396b 客户端链接层 —— 本仓(src-tauri + frontend)
- Rust(`license.rs` 既有验签):`channelConfig` 验签通过后落 `<appDataDir>` 缓存文件,**进 reset PRESERVE 名单**(同 `.license`/activation_state,T-363);验签失败弃用、保留旧缓存;缓存带 `version` schema 字段(不匹配即丢弃,走激活/心跳重取,向前兼容零迁移)。
- 前端新模块 `channel-links`:读缓存 → `getChannelLink(kind: "purchase" | "support" | "download"): string | null`。
- **改两处硬编码跳转**:
  - `frontend/src/app/activate/page.tsx` 的 `CONTACT_URL` → `supportUrl`:有则「联系授权方」;**null 则纯文案「请联系你的授权方获取激活码」,不渲染任何链接**(未激活时本就不知渠道,这正是代理要的不泄露)。
  - `frontend/src/features/settings/settings-interactive-region.tsx` 的 `PURCHASE_URL`(购买/续期)→ `purchaseUrl`:有则跳转;**null 则隐藏该入口**。
- 未激活 + 无缓存 → 中性降级(无链接无按钮)。
- 删除 `CONTACT_URL` / `PURCHASE_URL` 硬编码常量。
- 生效时延:`channelConfig` 随心跳刷新(内测码心跳 60min);后台改链接后「重启立即生效,不重启 ≤ 心跳周期」。
- **验收**:`pnpm verify` 相关包绿 + `license.rs` 测绿 + **打包产物字符串扫描 `#buy` / `creatoros.aitongban.cloud/#buy` 0 命中**(sidecar + 前端 bundle);null 不回退官方链接;假服务器坏签名 → 客户端拒用(Rust 测锚)。
